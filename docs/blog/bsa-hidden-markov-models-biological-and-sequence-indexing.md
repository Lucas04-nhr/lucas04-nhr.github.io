The Biological Sequence Analysis lectures from 29 September to 1 October connect three themes: probabilistic sequence models, their biological applications, and efficient sequence indexing. Together, they address two complementary problems: inferring the hidden process behind a sequence, and finding a query sequence efficiently within a large reference.

**Hidden Markov models (HMMs)** describe how unobserved states generate observations. **Suffix arrays, the Burrows–Wheeler transform (BWT), and FM-indexes** organize a reference sequence so that repeated searches do not require scanning the entire reference.

## Hidden states and observations {#hidden-states}

An observed sequence may contain regions generated by different underlying processes. A protein can alternate between hydrophobic and hydrophilic regions; a genomic sequence can contain intergenic regions, exons, and introns.

We observe the characters, but the region labels are hidden. An HMM represents both layers:

- a **state process**, which moves between hidden states;
- an **emission process**, which generates an observation from the current state.

For observations $x_1,\ldots,x_N$ and states $z_1,\ldots,z_N$, the model has the following parameters.

::: table align="center" title="HMM parameters"

| Parameter | Notation | Meaning |
| --- | --- | --- |
| Initial probability | $\pi_k$ | Probability of starting in state $k$ |
| Transition probability | $a_{kl}$ | Probability of moving from state $k$ to state $l$ |
| Emission probability | $e_k(b)$ | Probability of observing symbol $b$ in state $k$ |

:::

In the basic HMM considered here, the first-order Markov assumption means that the next state depends only on the current state. Conditional on its state, each observation is independent of the other states and observations.

For a fixed state path, the joint probability is

$$
P(x,z)=\pi_{z_1}e_{z_1}(x_1)
\prod_{i=2}^{N}a_{z_{i-1},z_i}e_{z_i}(x_i).
$$

Each transition row sums to one, and the emission probabilities within each state also sum to one.

### The occasionally dishonest casino {#casino}

The lecture uses a casino that switches between a fair and a loaded die. The die identity is hidden; the observed data are the rolls.

::: table align="center" title="The fair and loaded dice"

| Property | Fair state, F | Loaded state, L |
| --- | ---: | ---: |
| Probability of each outcome 1–5 | $1/6$ | $1/10$ |
| Probability of outcome 6 | $1/6$ | $1/2$ |
| Probability of staying in the same state | 0.95 | 0.90 |
| Probability of switching to the other state | 0.05 | 0.10 |

:::

A run of sixes supports the loaded state, but a single six does not determine the state. The fair die can also produce sixes, and the transition probabilities favor persistence. Inference combines the emission evidence with the cost of switching states.

### Signal peptides as a biological example {#signal-peptides}

A signal peptide illustrates how state-specific amino-acid preferences encode biological regions.

::: table align="center" title="Regions in the signal-peptide model"

| State | Region | Main characteristics |
| --- | --- | --- |
| N | N-terminal region | Positively charged; enriched in K and R |
| H | Hydrophobic region | Enriched in L, V, I, and F |
| C | Cleavage-associated region | Polar region containing the cleavage motif |
| M | Mature protein | More typical amino-acid composition |

:::

Emission probabilities represent composition, while model topology and transition probabilities represent the order and persistence of regions. Other lecture examples include gene structure, introgression, local ancestry, haplotype phasing, population-size histories, and identity by descent.

## Five questions for an HMM {#hmm-questions}

The lecture organizes HMM analysis around five distinct tasks.

::: table align="center" title="HMM questions and algorithms"

| Question | Method | Result |
| --- | --- | --- |
| How can a sequence be simulated? | Sampling from the model | A state path and observations |
| What is the most probable complete state path? | Viterbi | One globally optimal path |
| What is the probability of the observed sequence? | Forward | $P(x)$ |
| What is the probability of each state at each position? | Forward–Backward | $P(z_i=k\mid x)$ |
| How can parameters be estimated when states are unknown? | Baum–Welch | Updated model parameters |

:::

To simulate a sequence, sample the initial state from $\pi$, emit a symbol from that state's emission distribution, then sample the next state from the transition distribution. Repeat for the required sequence length.

For the following recurrences, the model generates a fixed-length sequence with no explicit end state. A model with an end state requires corresponding termination probabilities.

## Viterbi: the most probable path {#viterbi}

Viterbi finds

$$
z^*=\arg\max_zP(z\mid x)
=\arg\max_zP(x,z).
$$

The equality holds because $P(x)$ is constant across candidate state paths.

Define $v_k(i)$ as the highest joint probability among paths that generate the first $i$ observations and end in state $k$.

Initialization:

$$
v_k(1)=\pi_ke_k(x_1).
$$

Recurrence:

$$
v_k(i)=e_k(x_i)\max_l\left[v_l(i-1)a_{lk}\right].
$$

For every cell, record the predecessor state that achieved the maximum:

$$
\psi_k(i)=\arg\max_l\left[v_l(i-1)a_{lk}\right].
$$

Choose the final state with the largest $v_k(N)$, then follow the predecessor pointers backward to recover the complete path.

==**Viterbi optimizes an entire path, rather than choosing each position independently.**==

The predicted path need not equal the true path. In the casino example, short switching episodes may not provide enough evidence to overcome the transition probabilities, so some true switches are missed.

## Forward: the probability of the observations {#forward}

The probability of the observed sequence includes contributions from every possible hidden path:

$$
P(x)=\sum_zP(x,z).
$$

Enumerating all paths would be expensive. The Forward algorithm combines their contributions using dynamic programming.

Define

$$
f_k(i)=P(x_1,\ldots,x_i,z_i=k).
$$

Initialization:

$$
f_k(1)=\pi_ke_k(x_1).
$$

Recurrence:

$$
f_k(i)=e_k(x_i)\sum_lf_l(i-1)a_{lk}.
$$

Termination:

$$
P(x)=\sum_kf_k(N).
$$

Forward and Viterbi have almost the same recurrence structure. Their essential difference is **sum versus maximum**: Forward retains the total contribution of all paths, while Viterbi retains only the best path reaching each state.

## Backward and posterior state probabilities {#backward-posterior}

The Backward algorithm accounts for the observations after a position. Define

$$
b_k(i)=P(x_{i+1},\ldots,x_N\mid z_i=k).
$$

At the last position, there are no remaining observations:

$$
b_k(N)=1.
$$

The recurrence is

$$
b_k(i)=\sum_la_{kl}e_l(x_{i+1})b_l(i+1).
$$

Combining the prefix probability from Forward with the suffix probability from Backward gives

$$
\gamma_k(i)=P(z_i=k\mid x)
=\frac{f_k(i)b_k(i)}{P(x)}.
$$

At each position,

$$
\sum_k\gamma_k(i)=1.
$$

The lecture's posterior curves for the fair die show how confidence changes along the sequence. Unlike a single decoded path, these curves preserve uncertainty about state identity and transition boundaries.

::: table align="center" title="Three related dynamic-programming algorithms"

| Algorithm | Quantity stored | Main operation | Purpose |
| --- | --- | --- | --- |
| Viterbi | Best path probability ending in a state | Maximum | Decode a complete path |
| Forward | Total prefix probability ending in a state | Sum | Evaluate sequence likelihood |
| Backward | Remaining-observation probability given a state | Sum | Supply suffix evidence for posterior inference |

:::

::: note Path decoding and position-wise decoding
Choosing $\arg\max_k\gamma_k(i)$ separately at every position is posterior decoding. It is a different objective from Viterbi decoding. In a model with prohibited transitions, independently chosen labels can even form an invalid path.
:::

For $K$ states and $N$ observations, the standard dense recurrences require $O(NK^2)$ time. Long products can also become numerically tiny; implementations commonly use scaling or log-space calculations to avoid underflow.

## Parameter estimation and Baum–Welch {#parameter-estimation}

### When the states are known {#known-states}

If the observations and state labels are available, parameter estimation reduces to counting.

Let $A_{kl}$ be the number of observed transitions from $k$ to $l$, and let $E_k(b)$ be the number of times state $k$ emits symbol $b$.

$$
\widehat a_{kl}=\frac{A_{kl}}{\sum_jA_{kj}},
\qquad
\widehat e_k(b)=\frac{E_k(b)}{\sum_cE_k(c)}.
$$

The denominators are the relevant outgoing-transition and emission totals.

### When the states are unknown {#unknown-states}

Without state labels, transitions and emissions cannot be counted directly. Instead, count their expected contributions under the current model.

The posterior probability of a particular adjacent-state pair is

$$
\xi_{kl}(i)
=P(z_i=k,z_{i+1}=l\mid x)
=\frac{f_k(i)a_{kl}e_l(x_{i+1})b_l(i+1)}{P(x)}.
$$

Expected transition counts are

$$
\overline A_{kl}=\sum_{i=1}^{N-1}\xi_{kl}(i),
$$

and expected emission counts are

$$
\overline E_k(b)=\sum_{i=1}^{N}\gamma_k(i)\mathbf 1[x_i=b].
$$

For several training sequences, these quantities are added across sequences without introducing transitions between separate sequences.

**Baum–Welch** is the expectation–maximization (EM) algorithm for HMMs:

1. Initialize the model parameters.
2. Run Forward–Backward using the current parameters.
3. Compute expected transition and emission counts.
4. Normalize the counts to update the parameters.
5. Recalculate the log-likelihood and repeat until the change is small or an iteration limit is reached.

For independent sequences $x^{(1)},\ldots,x^{(J)}$, the objective is

$$
\ell(\theta)=\sum_{j=1}^{J}\log P(x^{(j)}\mid\theta).
$$

The lecture compares estimates from 300 and 30,000 casino rolls. The larger dataset produces parameters closer to the generating model. Baum–Welch still depends on initialization and is not guaranteed to find a global optimum.

## Designing, training, and decoding a biological HMM {#model-workflow}

The applications lecture separates three tasks that are easy to conflate. **Design** determines which states exist, what they can emit, and which transitions are allowed. **Training** estimates probabilities within that structure. **Decoding** applies the trained model to an observed sequence.

Training data do not automatically specify the biological architecture. A useful design starts with a hypothesis about the regions and signals that generated the sequence, including appropriate begin and end states.

::: table align="center" title="Parameters, posterior probabilities, and program roles"

| Quantity or operation | What it represents | How it is obtained |
| --- | --- | --- |
| Transition probability | Movement between hidden states | Estimated during training |
| Emission probability | Symbols generated by a state | Estimated during training |
| Posterior probability | State uncertainty given the complete sequence | Computed using the trained model |
| `trainanhmm` | Parameter estimation from a model specification and sequences | Labeled counting or unlabeled training |
| `decodeanhmm` | Prediction from a trained model and sequences | Viterbi or posterior decoding |

:::

For labeled data, pseudocounts can be added before normalization to avoid assigning zero probability to plausible events absent from a small training sample. If only coarse labels are available, several internal states may share a label; those labels do not necessarily reveal every internal state assignment.

For unlabeled data, the supplied software supports Baum–Welch and **Viterbi training**. Viterbi training alternates between finding a best path and updating parameters from that path. It differs from Baum–Welch, which uses expected counts over possible paths, and from Viterbi decoding, which predicts a path without itself updating parameters.

## Signal-peptide cleavage prediction {#cleavage-prediction}

The signal-peptide exercise turns the earlier composition example into a prediction task: identify where the signal peptide is cleaved from the mature protein.

### Start with a simple topology {#simple-signal-model}

The initial model follows

$$
B\rightarrow S\rightarrow C_{\mathrm{cut}}\rightarrow M\rightarrow E.
$$

Here $B$ and $E$ are begin and end states, $S$ represents the signal peptide, $C_{\mathrm{cut}}$ marks the cleavage-associated position, and $M$ represents the mature protein. Self-loops in $S$ and $M$ allow variable region lengths. The cleavage label represents a sequence position associated with the boundary; the physical cut lies between residues.

This model captures region order but assigns the same emission distribution throughout the signal peptide.

### Add biologically meaningful states {#signal-model-improvement}

The exercise progressively refines the topology.

::: table align="center" title="Progressive signal-peptide model designs"

| Design | Main state sequence | Biological feature represented |
| --- | --- | --- |
| Simple model | Signal → Cleavage → Mature | A single signal region and boundary |
| Region model | N → H → C-region → Cleavage → After | Distinct amino-acid preferences within the signal peptide |
| Pre-cleavage model | N → H → C-region → Cleavage−1 → Cleavage → After | A position-specific preference immediately before cleavage |

:::

Separating N, H, and C regions lets the model learn their different amino-acid compositions. Adding a dedicated pre-cleavage state lets it learn a local preference that would otherwise be diluted across the C region.

Multiple internal states can share one output label. For example, N, H, and C-region states can all represent the same coarse signal-peptide label, while retaining distinct emission distributions internally.

The lecture's region model gives a similar overall label-accuracy distribution to the simple model but slightly improves cleavage-site predictions. The pre-cleavage model gives a larger improvement, particularly for Viterbi. These are results from the demonstrated dataset, not a guarantee that every increase in model complexity improves prediction.

### Why posterior decoding can miss a cleavage site {#missing-cleavage}

In this exercise, every legal begin-to-end path passes through a cleavage state. Viterbi therefore predicts a cleavage position because it selects a complete legal path.

Posterior decoding selects the highest-probability state independently at each position:

$$
\hat z_i=\arg\max_k\gamma_k(i).
$$

Suppose plausible paths place the cleavage at several neighboring positions. The cleavage posterior can be spread across those positions, so it is never the largest state probability at any single position. Independent choices can then omit the cleavage label altogether, even though every legal path contains one.

==**Certainty that a boundary exists does not imply certainty about its location.**==

The distinction also explains why posterior-decoded labels can violate transition constraints. Viterbi's guaranteed cleavage prediction follows from this model's topology; it is not a universal property of Viterbi in all HMMs.

## Evaluating model predictions {#model-evaluation}

A confusion matrix shows which labels are mistaken for which others. In the lecture's convention, rows contain actual classes and columns contain predicted classes; correct predictions lie on the diagonal.

::: table align="center" title="Binary confusion matrix for a cleavage label"

| Actual class | Predicted cleavage | Predicted non-cleavage |
| --- | --- | --- |
| Cleavage | True positive, TP | False negative, FN |
| Non-cleavage | False positive, FP | True negative, TN |

:::

For multiple states or labels, the same layout extends to a larger matrix. Off-diagonal entries reveal overprediction, underprediction, and specific label confusions.

Overall residue accuracy and exact cleavage accuracy answer different questions. A protein may have almost all residues labeled correctly while its predicted cut is displaced by one residue. Because cleavage positions are rare, a high overall accuracy can hide poor boundary detection.

Useful evaluations therefore include residue-level confusion matrices, the distribution of accuracy across proteins, and the number of proteins with an exactly correct cleavage site.

### Training performance is not test performance {#cross-validation}

The exercise initially trains and decodes on the same data to demonstrate the programs. That measures fit to the training data and can overestimate performance on unseen sequences.

A better evaluation holds out data from training. In **five-fold cross-validation**, partition the data into five subsets, train on four, evaluate on the remaining subset, and repeat until every subset has been held out. Combine the held-out results to estimate predictive performance. A final model may then be retrained on all available data.

The slides describe leaving out one of five subsets. This is five-fold cross-validation, rather than leave-one-out cross-validation, which holds out one observation at a time. If model designs are selected using validation results, an independent final test set or an appropriate nested evaluation is needed for an unbiased final assessment.

## Gene finding in prokaryotes {#prokaryotic-gene-finding}

The next application is **de novo gene finding**: predict genes from sequence statistics and biological signals. Comparative approaches instead use homologous DNA or proteins, while experimental approaches use evidence such as RNA-seq.

De novo prediction can identify genes without known homologs or expression in a particular experiment, but its predictions are not direct experimental confirmation.

In the simplified prokaryotic model used in the lecture, a coding region is a continuous series of codons between a start and a stop. However, **open reading frames (ORFs) also occur in random sequences**, so finding an ORF alone does not establish a gene.

::: table align="center" title="Evidence for a prokaryotic coding region"

| Feature | Contribution |
| --- | --- |
| Codon usage | Distinguishes coding preferences from background composition |
| ORF length | Assesses how surprising a long stop-free stretch is |
| Ribosome binding site | Supports a candidate translation start |
| Start and stop signals | Constrains coding-region boundaries |

:::

### Codon usage and log-odds {#codon-usage}

For a codon $c$, a coding-versus-background score can be written as

$$
s(c)=\log_2\frac{P(c\mid\mathrm{coding})}{P(c\mid\mathrm{background})}.
$$

A positive score favors the coding model; a negative score favors the background model. Under an independent-codon approximation, the score for a region is the sum of its codon scores.

The lecture uses codon frequencies from *Aeropyrum pernix* to illustrate these differences. Background expectations must account for nucleotide composition: enrichment caused by GC content alone should not automatically be interpreted as coding evidence.

### Random ORF lengths {#random-orfs}

Assume independent triplets, each with stop probability $p_{\mathrm{stop}}$. The probability of seeing $n$ consecutive non-stop codons is

$$
P(\text{no stop in }n\text{ trials})=(1-p_{\mathrm{stop}})^n.
$$

With equally likely bases and the three standard stop codons,

$$
p_{\mathrm{stop}}=\frac{3}{64}.
$$

Thus long stop-free stretches become exponentially less likely. The probability of exactly $n$ non-stop codons followed by a stop is instead

$$
(1-p_{\mathrm{stop}})^n p_{\mathrm{stop}}.
$$

These expressions concern stopping behavior in a fixed frame; they do not include the probability of a preceding start codon.

AT content changes stop-codon frequencies and therefore changes the random ORF-length distribution. The lecture's comparison with *E. coli* shows why long ORFs are more informative than short ones, while length alone remains insufficient.

### A coding model needs sequence context {#coding-context}

A codon is a biological unit, and its three bases are not adequately described by three independent probabilities. The lecture factors its probability as

$$
P(x_1x_2x_3)=P_1(x_1)P_2(x_2\mid x_1)P_3(x_3\mid x_1x_2).
$$

The third position needs the previous two bases as context. For example, `TAA` is a stop codon while `TAT` encodes an amino acid, despite sharing their first two bases.

A gene model therefore needs both the three-position coding cycle and context-dependent emissions. High-order emission models or expanded states can represent this memory without abandoning a Markov representation of the hidden-state process.

The complete model combines intergenic sequence, an RBS module where appropriate, start signals, coding states, and stop signals. Viterbi then selects the most probable gene structure. The lecture presents GeneMark programs as examples of this modeling approach.

## Gene finding in eukaryotes {#eukaryotic-gene-finding}

Eukaryotic gene prediction requires more than detecting long genomic ORFs. Introns interrupt coding sequence; repeats and variation in GC content further complicate the background.

::: table align="center" title="Regions and signals in a eukaryotic gene model"

| Region or signal | Role |
| --- | --- |
| Promoter and transcription start | Describe the beginning of transcription |
| 5′ untranslated region | Transcribed sequence before translation starts |
| Start codon | Marks translation initiation |
| Coding exon | Carries coding-sequence statistics |
| Donor splice site | Marks the exon-to-intron boundary |
| Intron | Represents intervening sequence and its length properties |
| Acceptor splice site | Marks the intron-to-exon boundary |
| Stop codon | Marks translation termination |
| 3′ untranslated region and polyadenylation signal | Describe downstream transcribed sequence and processing signals |

:::

Transcription start and translation start are different boundaries. Likewise, a stop codon ends translation, not the entire transcript.

Splice-site signals can be modeled using weight matrices, neural networks, or HMMs. Predicting a complete gene requires connecting these local signals to coherent exon and intron structures.

The HMMgene diagrams progressively add donor, intron, and acceptor modules to a coding/intergenic model. Reading-frame consistency matters because an intron can occur between codons or interrupt a codon. Distinct phase configurations preserve the appropriate coding context when translation resumes in the next exon.

## Generalized HMMs and explicit lengths {#generalized-hmms}

In an ordinary HMM, repeated self-transitions implicitly define a state's duration. If the probability of remaining in state $k$ is $a_{kk}$, then

$$
P(L=\ell)=a_{kk}^{\ell-1}(1-a_{kk}),\qquad\ell\geq1.
$$

This is a geometric distribution: the probability of leaving is independent of how long the state has already lasted. It may be a poor description of some biological region lengths.

A **generalized HMM**, also called a hidden semi-Markov model in this context, explicitly models segment lengths. A state generates a whole segment rather than a single observation:

1. Choose a state using the transition model.
2. Choose its segment length from a state-specific distribution.
3. Generate a segment of that length using its sequence model.
4. Move to the next state.

The lecture presents **GenScan** as an example incorporating explicit length models, strand structure, and splice-site modeling.

The added flexibility increases computational cost because dynamic programming must consider candidate segment lengths. The extra cost depends on the allowed length range and whether segment probabilities can be reused efficiently. Geometric intron-length models can simplify part of this calculation.

## From biological prediction to sequence indexing {#sequence-indexing}

The indexing lecture asks how to locate a query string in a long reference efficiently. Let $m$ be the reference length, including the terminator where relevant, and $n$ the query length.

::: table align="center" title="String terminology"

| Term | Meaning | Example in `BANANA` |
| --- | --- | --- |
| Substring | Contiguous characters within a string | `ANA` |
| Prefix | A substring starting at the beginning | `BAN` |
| Suffix | A substring ending at the end | `NANA` |
| Alphabet | Set of available characters | $\{A,B,N\}$ |

:::

For DNA, the basic alphabet is $\{A,C,G,T\}$. Protein sequences use the amino-acid alphabet.

A tree is a connected graph with exactly one path between any pair of nodes. In a rooted tree, children descend from parents; leaves have no children. A node's **depth** is its distance from the root, while its **height** is the longest downward distance to a descendant leaf. The root has depth zero and leaves have height zero.

## Suffix tries and suffix trees {#suffix-trees}

A suffix index represents the suffixes of a reference. Adding a unique terminal symbol `$`, ordered before the other characters, distinguishes suffix endings even when one suffix would otherwise be a prefix of another.

### Suffix trie {#suffix-trie}

A suffix trie stores all suffixes in a shared tree. Each edge represents one character, and each root-to-leaf path spells a suffix. Suffixes with shared prefixes share an initial path.

To search for a query, start at the root and follow the query characters:

- matching all characters establishes that the query is a substring;
- matching the query followed by `$` establishes that it is a suffix;
- counting descendant leaves gives the number of occurrences;
- reporting their suffix-start labels gives the occurrence positions.

Searching takes $O(n)$ time, but the trie can require $O(m^2)$ construction time and space.

### Suffix tree {#suffix-tree}

A suffix tree compresses non-branching paths of the trie into single edges. An edge can therefore represent several characters, and non-root internal nodes have at least two children.

To keep storage linear, edge labels can be represented by intervals in the original reference rather than copied strings. Under the usual alphabet assumptions, suffix trees can be constructed in $O(m)$ time and space, with $O(n)$ pattern-search time.

A valid query can finish in the middle of an edge; it does not have to end at an explicit node. Reporting all occurrences adds work proportional to the output size.

## Suffix arrays {#suffix-arrays}

A suffix array stores the starting positions of suffixes in lexicographic order, rather than storing a tree.

Using 1-based positions for `BANANA$`:

::: table align="center" title="Suffix array for BANANA$"

| Rank | Suffix | Start position |
| ---: | --- | ---: |
| 1 | `$` | 7 |
| 2 | `A$` | 6 |
| 3 | `ANA$` | 4 |
| 4 | `ANANA$` | 2 |
| 5 | `BANANA$` | 1 |
| 6 | `NA$` | 5 |
| 7 | `NANA$` | 3 |

:::

Thus,

$$
SA=[7,6,4,2,1,5,3].
$$

All suffixes beginning with the same query occupy a contiguous interval. For `ANA`, the matching interval is ranks 3–4, corresponding to reference positions 4 and 2.

Binary search finds the interval boundaries. With direct character comparisons, the basic query complexity is $O(n\log m)$.

The lecture distinguishes naive construction, which can involve expensive suffix comparisons, from modern algorithms that can construct suffix arrays in linear time under suitable assumptions. Linear construction is not achieved simply by sorting copied suffix strings with a generic comparison sort.

## The Burrows–Wheeler transform {#bwt}

The BWT rearranges a string so that characters with similar following contexts tend to become grouped together.

Its conceptual construction is:

1. Append a unique `$` terminator.
2. Generate all cyclic rotations.
3. Sort the rotations lexicographically.
4. Take the last column of the sorted matrix.

For example,

$$
\texttt{BANANA\$}\longrightarrow\texttt{ANNB\$AA}.
$$

The first column is called $F$, and the last column is called $L$. The BWT is $L$.

==**BWT is a reversible rearrangement, not a compression algorithm by itself.**==

It preserves character counts, but often makes the result easier to compress. The unique terminator identifies the original rotation, allowing recovery of the original terminated string.

The full rotation matrix is an explanatory device, not something a practical index must store. Given a suffix array, each BWT character is the character immediately preceding that suffix, wrapping around at the start of the string.

## LF mapping and the FM-index {#lf-mapping}

The **last-to-first mapping**, or LF mapping, connects rows through corresponding occurrences of the same character in $L$ and $F$.

The key property is that the $r$th occurrence of a character in $L$ corresponds to its $r$th occurrence in $F$.

Define:

- $C[c]$: the number of characters in the terminated reference that are lexicographically smaller than $c$;
- $\operatorname{Occ}(c,i)$: the number of occurrences of $c$ in $L[1..i]$.

Using the lecture's 1-based indexing and inclusive prefix convention,

$$
LF(i)=C[L[i]]+\operatorname{Occ}(L[i],i).
$$

Also define $\operatorname{Occ}(c,0)=0$.

For `AGACCCATGACC$`, the BWT is `CGG$CCCACATAA`, and the character table is:

::: table align="center" title="C table for AGACCCATGACC$"

| Character $c$ | `$` | A | C | G | T |
| --- | ---: | ---: | ---: | ---: | ---: |
| $C[c]$ | 0 | 1 | 5 | 10 | 12 |

:::

For example, $L[6]=C$ and the first six BWT characters contain three Cs:

$$
LF(6)=C[C]+\operatorname{Occ}(C,6)=5+3=8.
$$

Following LF corresponds to moving one character backward in the original sequence, with cyclic wraparound. Repeated LF steps can reconstruct the string.

An **FM-index** combines a compressed representation of the BWT with the $C$ table, efficient rank/Occ queries, and typically sampled suffix-array information for locating matches.

::: note Indexing conventions
A 0-based implementation may use half-open intervals and an exclusive rank function. Its formulas will look different. Coordinate conventions, interval boundaries, and the definition of Occ must be used consistently.
:::

## Backward search: finding GACC {#backward-search}

FM-index search processes the query from right to left. At each step, it maintains the interval of sorted suffixes beginning with the part of the query already processed.

If the current interval is $[l,r]$, prepending a character $c$ updates it to

$$
l'=C[c]+\operatorname{Occ}(c,l-1)+1,
$$

$$
r'=C[c]+\operatorname{Occ}(c,r).
$$

If $l'>r'$, the interval is empty and the query has no exact match. Otherwise, continue until every query character has been processed.

For the first character $c$, initialize the interval to the block of rows beginning with $c$: from $C[c]+1$ to $C[c]+\text{count}(c)$.

The lecture searches for `GACC` in `AGACCCATGACC$`:

::: table align="center" title="Backward search for GACC"

| Step | Character added | Processed query suffix | Matching interval |
| ---: | --- | --- | --- |
| 1 | C | `C` | $[6,10]$ |
| 2 | C | `CC` | $[8,10]$ |
| 3 | A | `ACC` | $[2,3]$ |
| 4 | G | `GACC` | $[11,12]$ |

:::

For the second step,

$$
l'=5+\operatorname{Occ}(C,5)+1=5+2+1=8,
$$

$$
r'=5+\operatorname{Occ}(C,10)=5+5=10.
$$

For the third step,

$$
l'=1+\operatorname{Occ}(A,7)+1=2,
\qquad
r'=1+\operatorname{Occ}(A,10)=3.
$$

For the final step,

$$
l'=10+\operatorname{Occ}(G,1)+1=11,
\qquad
r'=10+\operatorname{Occ}(G,3)=12.
$$

The final interval contains

$$
12-11+1=2
$$

rows, so there are two exact occurrences. Their 1-based reference start positions are **2 and 9**.

==**The interval $[11,12]$ contains suffix-array ranks, not reference coordinates.**== Recovering coordinates requires suffix-array information or LF walks to sampled positions.

## Comparing the index structures {#index-comparison}

The lecture gives the following asymptotic costs and approximate memory estimates for a reference of roughly three billion bases.

::: table align="center" title="Sequence index time and space tradeoffs"

| Structure | Construction time | Space | Basic pattern-search time | Lecture memory estimate |
| --- | --- | --- | --- | --- |
| Suffix trie | $O(m^2)$ | $O(m^2)$ | $O(n)$ | Very large |
| Suffix tree | $O(m)$ | $O(m)$ | $O(n)$ | Over 15 bytes/base; about 45 GB |
| Suffix array | Can reach $O(m)$ | $O(m)$ | $O(n\log m)$ | About 4 bytes/base; about 12 GB |
| FM-index | $O(m)$ under suitable assumptions | $O(m)$, with compressed representations | $O(n)$ with constant-time rank | About 0.5 bytes/base; about 1.5 GB |

:::

The memory figures are illustrative, not universal. Actual storage depends on representation, coordinate width, alphabet, compression, and sampling.

For FM-indexes, the stated $O(n)$ search cost refers to finding the matching interval or counting matches when rank queries are constant-time. Locating every occurrence requires additional work. If rank has a nonconstant cost, that cost also enters the search complexity.

## From exact search to read alignment {#read-alignment}

The lecture ends by connecting indexing to seed-and-extend alignment.

For **BWA aln**, the slides describe an example using the first 32 nucleotides as a seed to find candidate matches, followed by alignment extension. This is a lecture example rather than a universal seed length for every invocation.

For **BWA MEM**, the slides emphasize finding multiple seeds, clustering compatible seeds, and extending candidates with local sequence alignment.

The distinction is between finding a promising location and producing a full alignment. Exact backward search finds identical strings. A complete read alignment may additionally contain mismatches, insertions, deletions, or clipping, so it requires more than one exact-index lookup.

## What to retain for the exam {#exam-checklist}

For HMMs, track what each state and dynamic-programming quantity represents. For biological applications, connect topology and emissions to the prediction target. For indexes, distinguish sorted rows from original sequence coordinates.

### Sequence indexing {#checklist-indexing}

1. Distinguish substrings, prefixes, suffixes, tree depth, and tree height.
2. Construct a small suffix trie, suffix tree, suffix array, and BWT.
3. Explain why matching suffixes form a contiguous sorted interval.
4. Compute the C table, Occ, and LF mapping with consistent indexing conventions.
5. Perform backward search and distinguish match intervals, counts, and reference coordinates.
6. Compare construction costs, memory requirements, and searching versus locating occurrences.
7. Explain how exact indexing supports candidate discovery before alignment extension.

HMMs provide a way to combine local sequence evidence with constraints on biological structure. Their usefulness depends on choosing states that capture the relevant biology and evaluating predictions on data excluded from training. Sequence indexes address the complementary computational problem of finding candidate locations efficiently. Together, these approaches make large-scale sequence analysis possible while keeping biological interpretation and algorithmic efficiency explicit.
