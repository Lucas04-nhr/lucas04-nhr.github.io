A profile HMM turns a family alignment into a probabilistic model with position-specific residue preferences and position-specific insertions and deletions. It is the method behind Pfam and HMMER, and the revision session stressed being able to draw a simple, correct diagram.

## From an Alignment to a Profile {#from-an-alignment-to-a-profile}

A protein family has conserved and variable positions, and a profile captures these position-specific preferences. For $L$ independent ungapped positions with emissions $e_i(a)$ and background $q_a$:

$$
P(X \mid M) = \prod_{i=1}^{L} e_i(x_i), \qquad
S(X) = \sum_{i=1}^{L} \log_2 \frac{e_i(x_i)}{q_{x_i}}
$$

This is a PSSM. For instance, $e_i(W) = 0.5$ against $q_W = 0.01$ contributes $\log_2 50 \approx 5.64$ bits. PSI-BLAST builds such a PSSM iteratively from detected homologues, but a PSSM has no probabilistic model of indels, and including false hits can make the profile drift.

Searching with a single sequence and BLOSUM assumes **position-independent** evolution. In a family MSA some positions are conserved and others variable, because function constrains the fold and the fold constrains the sequence (globins keep their function across human, cow and chicken). A profile summarises letter frequencies per column; a sequence is aligned to it with the same DP but a different score. The simplest score, the average substitution score $\sum_b f(b)\, s(b,a)$ (e.g. $\frac{5}{7}s(V,a) + \frac{1}{7}s(F,a) + \frac{1}{7}s(I,a)$), has no probabilistic foundation and treats conserved positions like the rest.

## Architecture {#architecture}

A profile HMM has an ordered backbone of core positions, and both transitions and emissions can be position-specific. Unlike the region-level HMMs above, its states are tied to positions in one family.

::: table align="center" title="Profile HMM states"

| State | Meaning | Consumes sequence / advances core |
| :--- | :--- | :--- |
| $M_i$ | Core position, emits a residue | Yes / yes |
| $I_i$ | Insertion after core position $i$ | Yes / no |
| $D_i$ | Deletion of core position $i$, silent | No / yes |

:::

A match state does not require identity; it can emit any residue with non-zero probability. Typical moves are $M_i \to M_{i+1}$, $M_i \to I_i \to M_{i+1}$ and $M_i \to D_{i+1} \to M_{i+2}$; $I_i \to I_i$ allows longer insertions and $D_i \to D_{i+1}$ consecutive deletions. Silent delete chains represent many possible skips with only $O(L)$ states and transitions.

If an insertion self-loop has probability $r$, then, given entry, the insertion length follows $P(\ell) = (1 - r) r^{\ell-1}$ for $\ell \ge 1$. Its log contribution is an opening term plus $(\ell - 1) \log r$, which is exactly the shape of an affine gap cost, but with position-specific parameters.

## Building from an MSA {#building-from-an-msa}

Select core columns (often by occupancy or conservation) and treat the rest as insertions. Read each sequence as a path of M, I and D states, count emissions and transitions, normalise, and regularise. Sequence weighting or redundancy reduction prevents a large cluster of close relatives from dominating.

**Small example.** Declare columns 1, 3 and 4 as core:

::: table align="center" title="Toy MSA read as state paths"

| | 1 | 2 | 3 | 4 | Path |
| :--- | :--- | :--- | :--- | :--- | :--- |
| $S_1$ | A | − | C | G | $M_1 M_2 M_3$ |
| $S_2$ | A | T | C | G | $M_1 I_1 M_2 M_3$ |
| $S_3$ | A | − | − | G | $M_1 D_2 M_3$ |

:::

$M_2$ emits C twice and $D_2$ emits nothing. From $M_1$, the raw outgoing counts give probability $1/3$ each to $M_2$, $I_1$ and $D_2$. The core length is 3 while observed lengths are 3, 4 and 2. Regularisation then removes unjustified zeros.

## Scoring, Alignment and Search Modes {#scoring-alignment-and-search-modes}

For a path $\pi$, $P(X, \pi \mid M)$ multiplies transition probabilities with emission probabilities of emitting states; silent states contribute transitions only.

$$
P(X \mid M) = \sum_\pi P(X, \pi \mid M), \qquad \pi^* = \arg\max_\pi P(X, \pi \mid M)
$$

Forward sums over all paths and Viterbi selects the best one, which also yields the alignment; both are compared with a null model as log-odds, computed in log space or with scaling. The sum is always at least the best single path. For sequence length $n$ and core length $L$, the sparse topology gives $O(nL)$ time and $O(nL)$ full-table space, or $O(L)$ memory for the score alone. Silent deletes advance the model index without advancing the sequence index.

Search modes are controlled by entry, exit and flanking transitions: *local* aligns part of the model to part of the sequence, *multiple local hits* capture repeated domains, and *glocal* aligns the full model (with indels) inside a longer sequence. HMMER provides the search tools and Pfam the family and domain models; good hits can be aligned back to extend the MSA.

Pfam 37.0 contains 21,979 families, each with a curated seed MSA, a profile HMM and a full alignment; it is now hosted by InterPro. HMMER provides `hmmbuild`, `hmmsearch` (profile against a sequence database), `hmmscan` (sequence against a profile database) and `jackhmmer` (iterative search); heuristic filters make it about as fast as BLAST, and HMMER3 reports Forward scores.

## Regularisation {#regularisation}

Not observing a residue in a small sample does not make it impossible. Pseudocounts prevent unjustified zeros and pull uncertain estimates toward a prior; they are not extra observations. With (possibly weighted) counts $c_i(a)$, $N_i = \sum_a c_i(a)$ and alphabet size $K$:

$$
e_i(a) = \frac{c_i(a) + 1}{N_i + K} \;\;(\text{add one}), \qquad
e_i(a) = \frac{c_i(a) + A q_a}{N_i + A} \;\;(\text{background prior})
$$

$A$ is the total prior strength. With no data the estimates fall back to uniform or background frequencies; with abundant data the empirical frequencies dominate. For example, two observations of A with a uniform DNA background and $A = 4$ give $e(\text{A}) = 3/6$ and $e(\text{C}) = e(\text{G}) = e(\text{T}) = 1/6$. Analogous priors apply to transitions, restricted to allowed outgoing moves and normalised per row.

A better prior uses the observed column composition to favour plausible substitutions. With $f_i(b) = c_i(b) / N_i$:

$$
\alpha_i(a) = A \sum_b P(a \mid b)\, f_i(b), \qquad
e_i(a) = \frac{c_i(a) + \alpha_i(a)}{N_i + A}, \qquad \sum_a \alpha_i(a) = A
$$

A column dominated by isoleucine therefore lends pseudocount mass to leucine and valine rather than spreading it uniformly, which is what makes profile HMMs effective at detecting remote family members from small seed alignments.

## Closing thoughts {#closing-thoughts}

Across all of these topics, the same few ideas keep returning. Dynamic programming turns exponential searches over alignments or state paths into tables filled in polynomial time. Log-odds scores compare a model of related or functional sequence with a background, which is why the choice of background changes conclusions in motif discovery, database search and gene finding alike. Heuristics such as seeds, indexes and progressive merging buy speed by discarding candidates early, and nothing later in the pipeline can recover what was discarded. Finally, every score, E-value or posterior is evidence under a model, not proof of homology, binding or function; being explicit about that distinction is usually what separates a good oral-exam answer from a merely correct one.

The substitution-matrix prior comes from the log-odds definition: $s(a,b) = \log \frac{P(a,b)}{q_a q_b} = \log \frac{P(a \mid b)}{q_a}$, so $P(a \mid b) = q_a e^{s(a,b)}$ (natural log, unscaled matrix). Dirichlet mixtures are the more advanced version of the same idea.

## Why a Profile HMM Rather Than a PSSM {#why-profile-hmm}

A PSSM has a fixed length and no model of insertions and deletions. A profile HMM scores indels probabilistically with position-specific costs (cheap in loops, expensive in the core), offers a full probabilistic framework (Forward over all alignments, Viterbi alignment, training, calibrated E-values) and supports local and glocal modes, which makes it much more sensitive for remote homologues.

Limitations: quality depends on the MSA, the choice of match columns, diversity, weighting and priors; positions are still independent, so residue–residue couplings are not modelled (Potts models in [Topic 10](/docs/ku-bsa/msa-and-coevolution/) address this); and a family hit suggests homology or domain membership, not exact function.

## Ten-Minute Presentation {#presentation}

### Keyword Card {#keyword-card}

- **Why**: function → fold → sequence; conservation is position-dependent; BLOSUM assumes position-independent
- **Profile** = per-column frequencies; same DP, new score; average score (no theory)
- **PSSM** $\sum\log\frac{e_i}{q}$ (W: 0.5/0.01 → 5.6 bits); PSI-BLAST iterative (drift); no indels
- **pHMM**: M (emit, conserved col), I (emit, self-loop), D (silent, skip); chained D → O(L) transitions
- **Position-specific** transitions/emissions; insert loop = **affine, position-specific**
- vs general HMM: states tied to family positions, left-to-right
- **Build**: match columns (<50% gaps) → paths → count → pseudocounts → normalise; **weighting**; toy: M1→M2/I1/D2 = 1/3 each
- **Search**: Forward (sum, score) / Viterbi (best path = alignment); log-odds vs null; $O(nL)$
- **Modes**: global, local, multi-local (repeats), glocal (domains)
- **Pfam** ~22k families, **HMMER** fast heuristics
- **Pseudocounts**: +1 (uniform ↔ data, "drown"); $\frac{c+Aq}{N+A}$; substitution: $P(a|b)=q_ae^{s}$, $\alpha_{ja}=A\sum_bP(a|b)f_{jb}$
- **Limits**: MSA quality/diversity, independence (no couplings), family ≠ function

### Full Script {#full-script}

::: details Full spoken script

My topic is profile hidden Markov models, the method behind Pfam and HMMER. The motivation is detecting distant homologs. Proteins in a family keep their function over evolution; function constrains the fold, and the fold constrains the sequence. But the constraints are not the same everywhere: in an alignment of a family — for example globins or SH3 domains — some positions are almost invariant and others vary freely. When we search with a single sequence and a substitution matrix like BLOSUM, we assume every position evolves in the same way. If we have a family alignment, we can use position-specific information and become much more sensitive.

A profile is a representation of an MSA that summarises the letter frequencies at each position. We can align a sequence to a profile with the same dynamic programming as before — only the score changes. One simple option is the average substitution score, for example five-sevenths of $s(V,a)$ plus one-seventh of $s(F,a)$ plus one-seventh of $s(I,a)$; but this has no real probabilistic foundation and treats conserved positions like the others. Better is a position-specific scoring matrix: the probability of a sequence segment is the product of position-specific emission probabilities, and the score is the log-odds against background:

$$
S=\sum_i\log_2\frac{e_i(x_i)}{q_{x_i}}
$$

A conserved tryptophan then gives a large reward: with probability 0.5 in the column and 1 percent in the background it scores log2 of 50, about 5.6 bits. PSI-BLAST uses this iteratively: search with BLAST, build a PSSM from the significant hits, search again with it, and repeat. But a PSSM has no proper model of insertions and deletions. A profile HMM solves exactly that.

We start from a chain of match states, one per conserved column of the alignment, each with its own emission distribution — that is just the PSSM written as an HMM. Then we add insert states between match states: they emit residues, typically with background-like probabilities, and they have a self-loop, so insertions of any length are possible. And we add delete states: these are silent — they emit nothing — and let a sequence skip a column. Because delete states are chained, a sequence can skip several columns with only a linear number of transitions, instead of connecting every match state to every later one. Every transition and emission is position-specific, so the model can say that gaps are common in a particular loop but very rare in the core. Notice the connection to pairwise alignment: entering an insert state costs one transition, and each extra residue costs the self-loop probability; in log space that is a gap opening cost plus a linear extension cost — affine gap penalties, but position-specific.

How is a profile HMM different from the HMMs of the previous lectures? In the casino or a gene finder, a few states represent types of region and are visited again and again. In a profile HMM, the states are tied to specific positions of one family, the model is strictly left-to-right, and its length equals the number of conserved columns.

Building it from an MSA: first decide which columns are match columns — for example columns with less than half gaps; the others are treated as insertions. Then each sequence becomes a path through match, insert and delete states, and we count.

For example, take three sequences — A-CG, ATCG and A--G — and declare columns 1, 3 and 4 as match columns. The first sequence is the path M1 M2 M3; the second is M1 I1 M2 M3, because its T is an insertion; and the third is M1 D2 M3, because it skips the second match column.

Here $M_2$ emits C twice; from $M_1$ one sequence goes to $M_2$, one to the insert state and one to the delete state, so each transition gets one third before regularisation. In the lecture's SH3 example, the conserved columns marked grey become match states. Two practical issues: many probabilities are estimated from very few counts, so we regularise; and if the family contains large clusters of near-identical sequences, they would dominate the counts, so we weight sequences or select a representative subset.

To search, we compute the log-odds score of a sequence against the model versus a null model — either with the Forward algorithm, which sums over all paths and is the proper probability of the sequence under the model, or with Viterbi, which gives the single best path — and that path is also the alignment of the sequence to the family, so good hits can be added to the MSA. The cost is proportional to the sequence length times the model length. The model can be used in different modes: global, local like Smith–Waterman, several local hits for repeated domains, or global in the model but local in the sequence, which is what we want for finding complete domains inside longer proteins. Pfam contains about twenty-two thousand families, each with an MSA and a profile HMM, and HMMER uses heuristic filters so it is about as fast as BLAST.

Finally, pseudocounts — the regularisation. If a residue never appears in a column of a small alignment, its probability should not be zero. The simplest fix is to add one to each count, which interpolates between a uniform distribution when we have no data and the observed frequencies when we have many — the pseudocounts "drown". Better is to add pseudocounts proportional to the background:

$$
e_j(a)=\frac{c_{ja}+A\,q_a}{\sum_{a'}c_{ja'}+A}
$$

Better still is to use the substitution matrix: a column full of isoleucines should give some probability to leucine and valine, but not to aspartate. From the log-odds definition $s(a,b)=\log\frac{P(a|b)}{q_a}$ we get $P(a|b)=q_ae^{s(a,b)}$; the pseudocount for $a$ is $A\sum_bP(a|b)f_{jb}$, mixing substitution probabilities according to the observed column frequencies. With few observations we rely on this prior knowledge; with many, the data dominate.

To conclude, a profile HMM combines position-specific residue preferences with position-specific insertion and deletion probabilities in one probabilistic model, which makes it much more sensitive than single-sequence or PSSM searches for distant homologs. Its limits: it depends on the quality and diversity of the MSA, it assumes positions are independent, so it does not model couplings between residues, and a hit indicates family membership, not exact function.

## Follow-up Questions {#follow-up-questions}

::: note How to use these questions

Questions marked ★ were raised in the revision sessions on 27 and 29 October. Answer directly first, then justify with the model, then name an assumption or limitation. Each answer is collapsed so the list can be used for self-testing.

::: collapse

- ★ Why use a profile HMM and not a PSSM?

  A PSSM has fixed length and no model of insertions/deletions (or ad hoc gap penalties); family alignments contain variable loops. A profile HMM adds insert and delete states with position-specific transition probabilities, so indels are scored probabilistically and differently in conserved cores vs loops; it is a full probabilistic model (Forward score over all alignments, Viterbi alignment, training, calibrated E-values) with local/glocal search modes — more sensitive for remote homologs.

- ★ How do you generate the profile (HMM)?

  Collect family members (e.g. BLAST/jackhmmer, curated seed) → build a good MSA → choose match columns (e.g. ≤ 50% gaps, or by MAP) → assign each sequence a path of M/I/D states → count emissions/transitions with sequence weights → add pseudocounts (Dirichlet / substitution-based) → normalise → calibrate null model/E-values (hmmbuild). Optionally iterate: search, add good hits, realign (Pfam seed → full).

- ★ Draw the profile HMM correctly (simple version).

  Begin → M$_1$ → M$_2$ → … → M$_L$ → End along the middle; insert states I$_0$…I$_L$ above (between match states) with self-loops; delete states D$_1$…D$_L$ below (silent). Transitions: M$_j$ → M$_{j+1}$, I$_j$, D$_{j+1}$; I$_j$ → I$_j$, M$_{j+1}$; D$_j$ → D$_{j+1}$, M$_{j+1}$ (Durbin also allows D→I and I→D; HMMER Plan 7 omits them). Insert states emit; delete states emit nothing. Keep it to 3 columns on the board.

- Why are delete states silent, and why use them at all?

  They represent skipping a consensus column, so they consume no residue. Without them, skipping $k$ columns would need direct jump transitions from each $M_j$ to every later $M_{j+k}$ — $O(L^2)$ parameters; chained delete states need only $O(L)$ and still allow any skip length.

- How do insert states relate to affine gap penalties?

  Entering $I_j$ costs $\log a_{MI}$, each extra residue $\log a_{II}$ (self-loop), leaving $\log a_{IM}$: log score = open + (ℓ−1) × extend → affine gaps, but with position-specific parameters (geometric length distribution).

- How does a profile HMM differ from a general HMM?

  States are tied to positions of one family (one M/I/D triple per consensus column), strictly left-to-right, position-specific parameters, length set by the MSA; general HMMs have few states representing region types with loops revisited (casino, gene finders).

- Forward or Viterbi for searching?

  Forward gives $P(x|M)$ summed over all alignments — more sensitive and the proper likelihood for log-odds/E-values (HMMER3 uses Forward scores). Viterbi gives the single best path = alignment to the model; used for alignment output and adding hits to the MSA.

- What search modes exist?

  Global (whole model, whole sequence), local (any part of model to any part of sequence; Smith–Waterman-like), multi-hit local (repeated domains), glocal (whole model, part of sequence — complete domains within multidomain proteins). Implemented with flanking N/C/J states and entry/exit transitions.

- Explain pseudocounts from substitution matrices.

  $s(a,b)=\log\frac{P(a,b)}{q_aq_b}=\log\frac{P(a|b)}{q_a}$ → $P(a|b)=q_ae^{s(a,b)}$ (natural log, unscaled). Pseudocount $\alpha_{ja}=A\sum_bP(a|b)f_{jb}$ mixes substitution probabilities weighted by observed frequencies; $e_j(a)=\frac{c_{ja}+\alpha_{ja}}{\sum c_{ja'}+A}$. A column of I's then gets pseudocounts mainly for L, V, M. Few counts → prior dominates; many → data dominate.

- Why sequence weighting?

  Families are sampled unevenly (many near-identical sequences from well-studied organisms); without weighting they dominate counts and bias the model toward one subfamily, reducing sensitivity to divergent members.

- What are Pfam and HMMER?

  Pfam: database of protein families/domains, each a curated seed MSA + profile HMM + full alignment (~22k families, InterPro). HMMER: software (hmmbuild, hmmsearch: profile vs sequence db, hmmscan: sequence vs profile db, jackhmmer: iterative); heuristic filters (MSV/SSV) make it about as fast as BLAST.

- What does PSI-BLAST do and what is profile drift?

  BLAST search → MSA/PSSM from significant hits → search with PSSM → iterate. If a false positive is included, the profile shifts towards an unrelated family (drift), pulling in more false hits.

- Limitations?

  Depends on MSA quality and match-column choice; assumes independence between positions (no long-range couplings — Potts models address that); limited for very divergent or highly variable families; hit = family membership, not exact function.
