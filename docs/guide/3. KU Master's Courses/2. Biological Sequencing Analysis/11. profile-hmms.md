## Which Family or Domain Does My Protein Belong To {#from-an-alignment-to-a-profile}

Family profiles improve remote-homology detection by modelling each position separately. Uses:

- **Annotate domains**: scan a protein against a library of family models (Pfam-style) and get, for each hit, the domain and its residue range.
- **Find remote members**: search a sequence database with one model.
- **Extend the alignment**: add a new sequence to the family alignment via its best path.

## Reading a Search Result {#reading-a-search-result}

A hit is a log-odds score against a null model with an E-value: read it like a BLAST hit, but the evidence comes from the whole family. The Viterbi path shows which residues occupy which core positions and where the domain starts and ends. A significant hit supports homology or domain membership; the specific function still depends on details such as whether catalytic residues are present.

## Practical Decisions When Building a Model {#building-from-an-msa}

Select core columns (often based on occupancy or conservation); the other columns become insertions. Read each sequence as an M/I/D path. Count emissions and transitions, normalise, then regularise. Weight sequences or reduce redundancy so that a large cluster of close relatives does not dominate the model.

> **Say:** Not seeing a residue in a small sample does not mean it is impossible. Pseudocounts prevent unjustified zeros and pull uncertain estimates toward a prior. They are not extra observations.

## Profile HMM Architecture {#architecture}

An ordered backbone represents core alignment positions; transitions and emissions can depend on position. Unlike a generic HMM with states for broad regions, ==states are tied to positions in a particular family==.

::: table align="center" title="Profile HMM states"

| State | Meaning | Consumes sequence / advances core |
| :--- | :--- | :--- |
| $M_i$ | Core position; emits residue | Yes / yes |
| $I_i$ | Insertion after core $i$; emits residue | Yes / no |
| $D_i$ | Deletion of core $i$; silent | No / yes |

:::

Match does not mean identity: $M_i$ can emit any residue with non-zero probability. Typical moves include $M_i \to M_{i+1}$, $M_i \to I_i \to M_{i+1}$ and $M_i \to D_{i+1} \to M_{i+2}$. $I_i \to I_i$ permits longer insertions; $D_i \to D_{i+1}$ permits consecutive deletions. Begin and end states delimit paths. Silent deletion chains represent many possible skips with only $O(L)$ states and transitions.

Profile HMM with three match columns. Insert states $I_0$–$I_3$ sit above with self-loops, match states $M_1$–$M_3$ run from Begin to End, and the silent delete states $D_1$–$D_3$ below let a path skip a column.

**Position-specific gap costs.** Entering an insert state costs $\log a_{MI}$ (gap opening) and each extra residue $\log a_{II}$ (extension). If an insertion self-loop has probability $r$, the insertion length given entry follows $P(\ell) = (1-r) r^{\ell-1}$ for $\ell \ge 1$: the shape of an affine gap cost, but with parameters learned per position, so a gap in a variable loop is cheap and a gap in the conserved core is expensive. Durbin et al. also allow D→I and I→D transitions, which HMMER's "Plan 7" architecture omits.

## Whiteboard Example: From MSA to Paths and Counts {#toy-msa}

Declare columns 1, 3 and 4 core:

::: table align="center" title="Toy MSA read as state paths"

| | 1 | 2 | 3 | 4 | Path (between begin/end) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| $S_1$ | A | − | C | G | $M_1 M_2 M_3$ |
| $S_2$ | A | T | C | G | $M_1 I_1 M_2 M_3$ |
| $S_3$ | A | − | − | G | $M_1 D_2 M_3$ |

:::

$M_2$ emits C twice; $D_2$ emits nothing. From $M_1$, raw outgoing counts give probability $1/3$ each to $M_2$, $I_1$ and $D_2$. The core length is 3; observed lengths are 3, 4 and 2. Alignment paths determine the counts; regularisation avoids unjustified zeros.

## Profile Score, Search and Cost {#scoring-alignment-and-search-modes}

For $L$ independent, ungapped positions with emissions $e_i(a)$ and background frequencies $q_a$,

$$
P(X \mid M) = \prod_{i=1}^{L} e_i(x_i), \qquad S(X) = \log_2 \frac{P(X \mid M)}{\prod_i q_{x_i}} = \sum_{i=1}^{L} \log_2 \frac{e_i(x_i)}{q_{x_i}}.
$$

This is a PSSM: positive contributions favour the family over background. Example: $e_i(W) = 0.5$ and $q_W = 0.01$ give $\log_2 50 \approx 5.64$ bits. PSI-BLAST iteratively builds a PSSM from detected homologues; a PSSM alone has no probabilistic indel model, and inclusion of false hits can cause profile drift.

**Forward** sums over all paths; **Viterbi** selects one best path and recovers its alignment. Both are compared with a null model using log-odds, and the sum is at least the largest path probability; use logs or scaling for numerical stability. To decide membership, Forward is the better measure, because for distant members no single alignment is clearly best.

For sequence length $n$ and core length $L$, the sparse profile topology gives $O(nL)$ DP time; score-only computation needs $O(L)$ memory.

**Search modes** are controlled by entry/exit and flanking/repeat transitions:

- **local**: part of the model against part of the sequence;
- **multiple local hits**: repeated domains in one protein;
- **glocal**: the full model (with indels) within a longer sequence.

HMMER supplies the search tools (`hmmbuild`, `hmmsearch`, `hmmscan`, `jackhmmer`); Pfam supplies family and domain models. Good hits can be aligned to add members to the MSA.

## Regularisation {#regularisation}

Let $c_i(a)$ be a (possibly weighted) residue count, $N_i = \sum_a c_i(a)$, and $K$ the alphabet size (20 for proteins). Two choices are

$$
\text{Add one: } e_i(a) = \frac{c_i(a) + 1}{N_i + K}, \qquad
\text{Background: } e_i(a) = \frac{c_i(a) + A q_a}{N_i + A}.
$$

$A$ is the total prior strength. With no data these give uniform or background probabilities; with abundant data the empirical frequencies dominate. Example: two A observations, DNA background $q_a = 1/4$ and $A = 4$ give $e(\text{A}) = 3/6$ and $e(\text{C}) = e(\text{G}) = e(\text{T}) = 1/6$. Apply analogous priors only to allowed outgoing transitions and normalise each row.

### Substitution-informed Pseudocounts {#substitution-pseudocounts}

Use the observed column composition to favour plausible substitutions. With $f_i(b) = c_i(b)/N_i$,

$$
\alpha_i(a) = A \sum_b P(a \mid b)\, f_i(b), \qquad
e_i(a) = \frac{c_i(a) + \alpha_i(a)}{N_i + A}, \qquad \sum_a \alpha_i(a) = A.
$$

A column dominated by leucine thus lends pseudocount mass to isoleucine and valine rather than to aspartate. An unscaled natural-log score $s(a,b) = \ln[P(a \mid b)/q_a]$ gives $P(a \mid b) = q_a e^{s(a,b)}$; a real matrix's log base and scaling must be accounted for. With $N_i = 0$, use a specified prior instead of undefined empirical frequencies.

Too little regularisation gives a model that only recognises its training sequences; too much blurs the conserved positions.

## Why a Profile HMM Rather Than a PSSM {#why-profile-hmm}

A PSSM has a fixed length and no model of insertions and deletions. A profile HMM scores indels probabilistically with position-specific costs, offers a full probabilistic framework (Forward over all alignments, Viterbi alignment, training, calibrated E-values) and supports local and glocal modes, which makes it more sensitive for remote homologues.

**Limitations**: quality depends on the MSA, core selection, sequence diversity and prior strength. Standard emissions do not capture long-range residue couplings (coupling models in [MSA and Co-evolution](/docs/ku-bsa/msa-and-coevolution/) address this). A significant family hit supports homology or domain membership; exact function still needs biological evidence.

## Ten-Minute Presentation {#presentation}

### Full Script {#full-script}

::: details Full spoken script

**What it is for.** Suppose I have a new protein and a BLAST search finds nothing convincing. The protein may still belong to a known family. A family is not defined by any single member but by a pattern: some positions are almost invariant, others accept any hydrophobic residue, some regions often carry insertions. A profile HMM is a statistical description of this pattern, built from the family's multiple alignment. Comparing my protein with the profile uses the information of the whole family, and that makes it more sensitive for distant relatives than any pairwise comparison. This is how domain databases such as Pfam and the HMMER software work.

**Three uses.** First, annotation: I scan my protein against a library of family models and get, for each hit, which domain it is and from which residue to which residue it extends. Second, searching: I take one family model and search a sequence database to find new, remote members. Third, alignment: the best path of a sequence through the model tells me which residue corresponds to which column, so I can add new sequences to an existing family alignment.

**From weight matrix to profile HMM.** A weight matrix already describes position-specific preferences, but it has a fixed length and cannot handle insertions and deletions, which are normal between family members. The profile HMM adds exactly that. For each conserved column of the alignment there are three states. The match state emits a residue with that column's probabilities; match does not mean identical, it means this residue occupies this family position. The insert state emits extra residues between two columns, and has a self-loop so insertions can be long. The delete state emits nothing and simply skips the column. A sequence is then explained by a path from left to right through these states.

**Why this is better than fixed gap penalties.** In pairwise alignment a gap costs the same everywhere. In a profile HMM the transition probabilities into insert and delete states are specific to each position, learned from the family. So a gap in a loop where family members often differ in length is cheap, and a gap in the middle of a conserved core is expensive. The self-loop of the insert state corresponds to a gap-extension cost, so the model contains position-specific affine gap penalties.

**Building the model.** I start from a multiple alignment. I decide which columns are core columns, usually those where most sequences have a residue; the others are treated as insertions. Then every sequence in the alignment is a known path, and I count. In the small example with three sequences, ACG, ATCG and AG, and columns one, three and four chosen as core: the first sequence goes match, match, match; the second has an insertion after the first match; the third deletes the second core position. So from the first match state I observe one transition to match, one to insert and one to delete. Counts are turned into probabilities, sequences are weighted so that a cluster of near-identical ones does not dominate, and the estimates are regularised.

**Regularisation.** With twenty amino acids and often only a few dozen sequences, many residues are never observed in a given column. Not observed does not mean impossible, and a zero probability would reject a true family member because of one substitution. So I add pseudocounts. The simplest is to add one to every count. Better is to add them in proportion to the background frequencies. Better still is to use a substitution matrix: if the column contains leucine, the pseudocounts favour isoleucine and valine more than aspartate, because those substitutions are known to be common. The strength of the prior matters in practice: with few sequences it dominates, with many the data take over; too little regularisation gives a model that only recognises the training sequences, too much blurs the conserved positions.

**Searching and reading a hit.** To score a sequence I can use Viterbi, which gives the probability of the single best path and at the same time the alignment to the model, or Forward, which sums over all paths and is the better measure of whether the sequence belongs to the family. Either is divided by the probability under a null model of random sequence, and the logarithm is reported as a bit score with an E-value, which I read just like in BLAST. The cost is proportional to the sequence length times the model length. Because a domain is usually only part of a protein, the model is given flanking states that absorb the rest of the sequence, so it can match locally and several times in one protein. A significant hit tells me that the region is homologous to the family domain; the specific function still depends on the details, for example whether the catalytic residues are present.

:::

## Follow-up Questions {#follow-up-questions}

::: note How to use these questions

Questions marked ★ were raised in the revision sessions on 27 and 29 October. Answer directly first, then justify with the model, then name an assumption or limitation. Each answer is collapsed so the list can be used for self-testing.

:::

::: collapse

- Why is a profile HMM more sensitive than BLAST?

  BLAST compares my sequence with one sequence at a time using the same substitution matrix and gap costs everywhere. A profile HMM knows, from the whole family, what is tolerated at each position and where gaps are common. A distant member that matches the conserved positions scores well even if its overall identity to every single member is low.

- ★ Why use a profile HMM and not a PSSM?

  A PSSM has a fixed length and no model of insertions and deletions, while family alignments contain variable loops. A profile HMM adds insert and delete states with position-specific transition probabilities, so indels are scored probabilistically and differently in conserved cores and loops; it is a full probabilistic model with Forward scores, Viterbi alignments, training, calibrated E-values and local/glocal search modes.

- What do the three types of states do, and which of them emit?

  Match states emit a residue for a core column, insert states emit residues between core columns, delete states are silent and skip a core column. So match and insert consume a residue of the sequence; match and delete advance along the model.

- ★ Draw the profile HMM correctly (simple version).

  Begin → $M_1$ → $M_2$ → $M_3$ → End along the middle; insert states $I_0 \ldots I_3$ above with self-loops; silent delete states $D_1 \ldots D_3$ below. Transitions: $M_j \to M_{j+1}, I_j, D_{j+1}$; $I_j \to I_j, M_{j+1}$; $D_j \to D_{j+1}, M_{j+1}$. Insert states emit; delete states emit nothing. Keep it to three columns on the board.

- How are gaps treated differently from pairwise alignment?

  Through transition probabilities that differ from position to position. Entering an insert or delete state plays the role of gap opening, staying in it the role of extension, and both are learned from where the family actually has insertions and deletions.

- ★ How do you generate the profile HMM?

  Collect family members (e.g. a curated seed or iterative search) → build a good MSA → choose match columns (e.g. by occupancy) → assign each sequence an M/I/D path → count emissions and transitions with sequence weights → add pseudocounts (background- or substitution-based) → normalise → calibrate the null model and E-values (`hmmbuild`). Optionally iterate: search, add good hits, realign.

- Why do we need pseudocounts, and why use a substitution matrix for them?

  Because with few sequences many residues have zero counts in a column, and zero probability would exclude true members. Pseudocounts based on a substitution matrix put the added probability on residues that are chemically similar to those observed, which is more realistic than spreading it evenly.

- Would you use Viterbi or Forward to decide whether a protein belongs to the family?

  Forward, because it adds the evidence from all possible alignments to the model; for distant members no single alignment is clearly best and the Viterbi score underestimates the support. I use Viterbi or posterior decoding to get the actual alignment and the domain boundaries.

- Your protein hits a kinase domain model with a very low E-value. Is it an active kinase?

  The hit shows that the region is homologous to kinase domains. Whether it is active depends on specific residues; I would check in the alignment to the model whether the known catalytic positions carry the required residues, since inactive pseudokinases also match the profile.

- What can a profile HMM not represent?

  Dependencies between positions that are far apart in the sequence, such as co-evolving contact pairs, because each match state emits independently. It also depends entirely on the quality and diversity of the alignment it was built from.

:::
