Searching a database with full dynamic programming is too slow, so BLAST and BLAT are heuristics built on **seed and extend**: find short word matches by table lookup and align in detail only around them. The page starts with which tool and settings suit which task and how a hit list is read, then follows one BLAST hit from seed to extension, and ends with how word length trades sensitivity against speed.

::: tip Opening

Suppose I have a protein of unknown function and want to find related sequences that could tell me what it does, or I have an mRNA and want to find where it lies in a genome. Both are database searches, and full dynamic programming would be too slow. I will start with which tool and settings suit which task and how the hit list is read, then follow one BLAST hit from seed to extension, and end with how word length trades sensitivity against speed.

:::

## Which Search for Which Task {#choosing-a-method}

::: table align="center" title="Search methods compared"

| Task | Practical choice |
| :--- | :--- |
| Unknown protein; remote homologues | Protein BLAST with neighbourhood words |
| Near-identical DNA/mRNA in a genome, many queries | BLAT: pre-indexed genome |
| Few comparisons, no true hit may be missed | Smith–Waterman (no heuristic) |
| More sensitivity / more speed | Shorter / longer seed words |

:::

Smith–Waterman costs $O(lL)$ for query length $l$ and total database length $L$. Heuristics restrict detailed alignment to candidate regions and ==can miss true matches==.

## Reading the Hit List {#significance}

A large database gives many opportunities for chance matches. The **E-value** is the expected number of chance matches scoring at least $S$:

$$
E(S) = Kmn\,e^{-\lambda S}, \qquad P(\text{at least one}) \approx 1 - e^{-E(S)}.
$$

$m$ and $n$ are the effective query and database lengths; $K$ and $\lambda$ are parameters of the scoring system and background. A higher score gives an exponentially smaller $E$. A tenfold larger database gives approximately a tenfold larger $E$, other factors fixed.

$E$ is an expected count, can exceed 1, and is not the probability that the sequences are unrelated. For small $E$, $P \approx E$. Significance does not establish identical function.

Read a hit in this order:

1. **E-value**: is the hit better than chance in this search?
2. **Coverage**: does the alignment span the whole protein or only one domain?
3. **Identity** and the alignment itself. One database sequence can give several HSPs.

The search is heuristic: ==no hit is not evidence of absence==. Details of the statistics are on the [score statistics page](/docs/ku-bsa/score-statistics/).

## Practical Settings: Word Length, Threshold, Indexing {#fast-lookup-and-the-seed-length-trade-off}

- Short words increase sensitivity but generate many chance hits; long words reduce random matches but miss divergent regions.
- **Low-complexity masking** suppresses repetitive, uninformative seeds.
- **Database indexing** spends memory to accelerate repeated queries.

Indexing the query (BLAST) suits one query against a changing database; indexing the database (BLAT) suits many queries against one genome. Requiring two nearby hits on one diagonal allows shorter words without a flood of random extensions (see [below](#choosing-the-word-length)).

## BLAST: From Words to Seeds {#blast-step-by-step}

BLAST stands for Basic Local Alignment Search Tool.

::: steps

1. Mask low-complexity regions; generate overlapping query words (3 residues for proteins).
2. For proteins, generate the **neighbourhood**: all words scoring at least a threshold $T$ against a query word under a substitution matrix such as BLOSUM62.
3. Scan the database for exact occurrences of retained words, using a lookup table so each position needs one lookup.
4. Extend promising hits into **high-scoring segment pairs** (HSPs), process candidates further (gapped extension), and report alignments with their significance.

:::

A database word need not equal the original query word: it exactly matches one of the query word's retained neighbours. Lowering the word-score threshold usually increases sensitivity and computation.

**Whiteboard example.** For the query word PQG, the neighbour PEG scores $7 + 2 + 6 = 15$ under BLOSUM62, so Q/E is accepted if 15 meets the threshold. Extending the seed tests whether it belongs to a longer high-scoring segment:

::: table align="center" title="Ungapped extension of the PQG/PEG seed"

| | Flank | | | Seed | | | Flank |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| Query | R | P | P | Q | G | L | F |
| Database | D | P | P | E | G | V | V |
| Score | −2 | 7 | 7 | 2 | 6 | 1 | −1 |

:::

The five-residue segment PPQGL/PPEGV scores 23 and is an HSP in this ungapped example. The seed is only a starting point: extension checks whether the surrounding sequence supports a longer high-scoring region. A negative substitution need not stop extension immediately; ungapped extension stops when the running score drops more than $X$ below the best score seen so far (X-drop). Further processing can produce gapped local alignments, and one sequence pair can contain several locally similar regions with separate scores.

## BLAST Programs and the Taq Exercise {#blast-programs}

::: table align="center" title="BLAST programs"

| Program | Query | Database |
| :--- | :--- | :--- |
| blastn | DNA | DNA |
| blastp | Protein | Protein |
| blastx | Translated DNA (six frames) | Protein |
| tblastn | Protein | Translated DNA (six frames) |
| tblastx | Translated DNA | Translated DNA |

:::

In the exercise, Taq polymerase was **not** found in *E. coli* with blastn but **was** found with tblastn. Protein-level comparison is more sensitive for distant relatives because synonymous changes alter DNA but not protein, and substitution matrices reward conservative replacements. Changing the blastn reward/penalty from 2/−3 to 1/−4 split one hit into two shorter, higher-identity HSPs, because local alignment stops extending into mismatch-rich regions. The uncovered query region 256–430 turned out to be the exonuclease domain, so the domain architecture differs (checked with Pfam).

## BLAT: Index the Genome and Combine Hits {#blat-index-the-genome-instead-of-the-query}

BLAT stands for BLAST-Like Alignment Tool. It reverses the roles:

- Keep a hash of **non-overlapping** target words of the genome in memory, omitting very common repeats.
- Generate **overlapping** query words, look up their genomic positions, group compatible hits and extend.
- Lecture examples: DNA 11-mers, protein 4–5-mers. The target index is reused for many queries.

BLAT suits high-identity genome and transcript mapping, such as an mRNA against its own genome; it can require several nearby hits before extending and joins aligned blocks across introns. BLAST supports broader similarity searches.

## Missed True Hits versus Random Hits {#choosing-the-word-length}

Let $q$ be the identity per position, $w$ the number of independent word opportunities, and $p = q^k$ the probability that a word of length $k$ matches. Then the number of matching words is $X \sim \text{Binomial}(w, p)$:

$$
\begin{aligned}
P(X = 0) &= (1-p)^w, \qquad P(X = 1) = wp(1-p)^{w-1}, \\
P(\text{miss if two hits required}) &= (1-p)^w + wp(1-p)^{w-1}.
\end{aligned}
$$

One-hit detection is $1 - P(X=0)$; two-hit detection is $1 - P(X=0) - P(X=1)$. Increasing $k$ lowers $q^k$: fewer random hits but more missed true matches. Requiring two hits also costs some sensitivity. These are approximations, since overlapping words are dependent.

With alphabet size $M$ and uniform independent letters, a random word matches with probability $M^{-k}$. For target length $L$ and query length $l$,

$$
E(\text{random seed pairs}) \approx \frac{L}{k}\,(l - k + 1)\,M^{-k}.
$$

Requiring hits close together on the **same diagonal** ($j - i$ constant for ungapped matches), rather than anywhere, makes independent random coincidences much rarer. Shorter $k$ combined with this filter recovers sensitivity while controlling extension work; gapped BLAST's two-hit method uses a window of about 40 residues. Indels shift the diagonal, which chaining or gapped alignment handles.

**FASTA comparison.** FASTA finds exact word hits, identifies high-scoring diagonals, rescores and joins nearby regions, then runs Smith–Waterman in selected windows. The lecture uses $k = 1$–2 for proteins and 4–6 for DNA. The final optimal refinement cannot rescue regions discarded during heuristic filtering.

## Ten-Minute Presentation {#presentation}

### Full Script {#full-script}

::: details Full spoken script

**What it is for.** Suppose I have a protein of unknown function and want to find related sequences that could tell me what it does. Or I have an mRNA and want to know where it lies in a genome. Both are database searches: one query against millions of sequences. Smith–Waterman would give the best local alignment, but its cost is proportional to the query length times the total database length, which is far too slow at this scale. Tools such as BLAST and BLAT are therefore heuristics: they are much faster because they only do detailed alignment where there is already some evidence of similarity, and the price is that they can miss a true match.

**The common idea: seed and extend.** Two sequences that are similar over a region will almost always share at least one short word that matches exactly or nearly exactly. So the search has four steps: make a list of words from the query, find where these words occur in the database, extend each of these seed hits into a longer alignment, and evaluate whether the result is statistically significant. Finding the seeds is fast because the words are stored in a lookup table, a hash, so each database position needs only one lookup instead of a comparison with every query word.

**Which tool for which task.** For a protein of unknown function I use protein BLAST, because protein comparison is more sensitive than DNA comparison for distant relatives: the substitution matrix recognises conservative replacements. For locating an mRNA or a nearly identical DNA sequence in a genome, and especially for many queries against the same genome, I use BLAT, which keeps an index of the whole genome in memory. If I have only a few comparisons and cannot afford to miss anything, I use Smith–Waterman without any heuristic.

**How BLAST works.** BLAST first masks low-complexity regions of the query, because repetitive segments would produce many meaningless hits. It then cuts the query into overlapping words, three residues for proteins. For proteins it does not only use the words themselves: for each query word it generates the neighbourhood, all words that score at least a threshold $T$ against it under the substitution matrix. It then scans the database for exact occurrences of any word in this list. So a database word does not need to be identical to the query word; it must be identical to one of its high-scoring neighbours. Each hit is extended in both directions without gaps into a high-scoring segment pair, an HSP, and promising HSPs are then extended with gaps and given a score and an E-value.

**A small example.** Take the query word PQG. Under BLOSUM62 the word PEG scores $7+2+6 = 15$ against it, so if the threshold is below that, PEG is in the neighbourhood, and a database sequence containing PEG produces a seed hit. Now I extend: if the residues around the seed are also similar, say the segment PPQGL against PPEGV, the score rises to 23; if the flanking residues score negatively the extension stops. The seed is only a starting point; the extension tests whether the surrounding sequence supports a longer similar region.

**How BLAT differs.** BLAT turns the roles around: it builds an index of non-overlapping words of the genome once and keeps it in memory, then looks up the overlapping words of each query. This is very fast for many queries against one genome. It is designed for sequences that are very similar to the genome, such as mRNA against its own genome, so it can require several nearby hits before it extends, and it joins the aligned blocks across introns.

**The central trade-off: word length.** Short words make the search sensitive, because even diverged regions still contain a short matching word, but they also match by chance everywhere, so the program wastes time on extensions. Long words give few random hits and a fast search but miss diverged homologues. I can make this quantitative. If the two sequences are identical at each position with probability $q$, a word of length $k$ matches with probability $p = q^k$. With $w$ independent word positions the chance of finding no matching word at all is $(1-p)^w$: that is the probability of missing a true homologue. On the other side, the expected number of random seed hits is roughly the number of word pairs times $M^{-k}$ for an alphabet of size $M$. A good compromise is to use shorter words but require two hits close together on the same diagonal before extending: two independent random hits on one diagonal are much rarer than one.

**How I read the output.** For each hit I look first at the E-value, the number of hits this good that I would expect by chance in this search. Then at the coverage: does the alignment span the whole protein or only one domain? Then at the identity and the alignment itself. One database sequence can give several HSPs. And because the method is heuristic, finding no hit does not prove that no homologue exists; I could repeat the search with more sensitive settings or with a profile method.

:::

## Follow-up Questions {#follow-up-questions}

::: note How to use these questions

Questions marked ★ were raised in the revision sessions on 27 and 29 October. Answer directly first, then justify with the model, then name an assumption or limitation. Each answer is collapsed so the list can be used for self-testing.

:::

::: collapse

- Why is BLAST faster than Smith–Waterman, and what do we lose?

  It does detailed alignment only around seed hits found by table lookup, instead of filling a dynamic-programming table for the whole database. We lose the guarantee of finding the optimal local alignment: a homologue without any word hit above the threshold is missed.

- What are neighbourhood words and why are they used for proteins?

  All words that score at least $T$ against a query word under the substitution matrix. Related proteins often differ by conservative substitutions, so requiring an identical three-letter word would miss many of them; the neighbourhood lets a similar but not identical word start an alignment while the database lookup itself stays exact.

- What happens if I lower the threshold $T$ or shorten the word?

  More seed hits: sensitivity goes up because weaker similarities now produce a seed, but so does the number of random hits and therefore the running time.

- What is the difference between BLAST and BLAT in what they index?

  Classical BLAST builds the lookup table from the query words and scans the database. BLAT builds the index from the genome once and looks up the query words. Indexing the database costs memory but pays off when many queries are run against the same genome.

- ★ When do you use BLAST vs BLAT?

  BLAT for DNA (or very similar protein) searches against a genome when the match is expected to be near-identical: mapping mRNA or ESTs to the genome, locating a sequence, many queries against the same genome. It is fast because the genome is pre-indexed but insensitive to divergent homologues. BLAST for general similarity searches, especially proteins and distant homologues, because neighbourhood words find similar-but-not-identical seeds.

- Why require two hits on the same diagonal?

  An ungapped alignment lies on one diagonal, so a true similar region tends to give several hits on the same diagonal close together, while random hits are scattered. Requiring two reduces random extensions dramatically, which allows shorter and therefore more sensitive words at the same cost.

- ★ With seed-and-extend, if there are multiple seeds on one diagonal, is there any distance requirement?

  Yes. In the two-hit method of gapped BLAST, extension is triggered only by two non-overlapping word hits on the same diagonal within a window $A$ (about 40 residues). Same diagonal means equal offset $j-i$, consistent with one ungapped alignment; the distance limit ensures they could belong to the same HSP. Indels shift the diagonal, so later gapped extension or chaining handles that.

- ★ Mention hash tables, suffix trees, suffix arrays — where do they appear in BLAST/BLAT?

  BLAST builds a lookup table of the query's neighbourhood words and scans the database. BLAT builds a hash table of non-overlapping $k$-mers of the genome kept in memory. Suffix trees, suffix arrays and the BWT/FM-index are the basis of NGS read mappers (BWA, Bowtie) and allow exact queries of arbitrary length.

- ★ What is the time complexity?

  Smith–Waterman against the database: $O(lL)$. BLAST: building the word list depends on $l$ and $T$, scanning the database is $O(L)$ with $O(1)$ lookups, plus extension work proportional to the number of hits, so roughly linear in $L$ with a much smaller constant than DP. BLAT: each query word is an $O(1)$ hash lookup, so query time is roughly independent of genome size, but memory is $O(L)$.

- With 80% identity and word length 10, how likely is a given word to match?

  $p = 0.8^{10} \approx 0.107$. With, say, $w = 10$ independent word positions the chance of no match is $(1 - 0.107)^{10} \approx 0.32$, so about one third of such regions would be missed by a single-hit rule with this word length.

- You get no hits for your protein. What do you conclude and do?

  Not that the protein has no homologues. I would relax the E-value cutoff and word settings, check whether masking removed most of the query, and try a more sensitive profile-based search, for example a profile HMM against a family database.

:::
