A sequencing run produces millions of short reads that say nothing until each is placed in the reference genome with a known confidence. This topic has two halves: the practical workflow, with the files and quality values read at each step and the decisions they support, and the index (the Burrows–Wheeler transform and FM-index) that makes searching a whole genome fast enough.

::: tip Opening

Suppose I have sequenced a human sample, or an ancient bone, and obtained millions of short reads. To call variants I must first decide where each read comes from in the reference genome and how much I trust that placement. I will start with the practical workflow, the files and quality values I read at each step and the decisions they support, and then explain how the BWT and FM-index make it possible to search a whole genome fast enough.

:::

## From Reads to Variants {#data-quality-and-workflow}

**Workflow**: sample → library → sequencing → FASTQ → quality control / adapter trimming → reference mapping → SAM/BAM → filtering and variant/genotype inference → VCF.

- **FASTA**: identifiers and sequences (e.g. the reference). **FASTQ**: four lines per read — read ID, sequence, `+`, per-base quality string.
- **SAM/BAM**: text/binary alignment records with reference, position, flags/strand, MAPQ, CIGAR, sequence and base qualities. **VCF**: variants and genotypes.

**Base quality** describes uncertainty in a nucleotide call; **mapping quality** (MAPQ) describes uncertainty in genomic placement. Both use the Phred scale:

$$
Q = -10 \log_{10} P(\text{error}), \qquad P(\text{error}) = 10^{-Q/10}.
$$

Q20 means 1% error and Q30 0.1%. FASTQ usually encodes $Q$ as ASCII($Q + 33$). ==A repetitive read can have excellent base qualities but low MAPQ==: placement and base-call certainty are different questions.

**Depth** is the number of reads covering a position; **coverage breadth** is the fraction of positions covered. Under uniform independent sampling, $D \sim \text{Poisson}(\lambda)$ and $P(D \ge 1) = 1 - e^{-\lambda}$, so a mean depth does not guarantee that every site is covered. **Library complexity** counts distinct original molecules; duplicates add reads without independent evidence.

**Reading records.** SAM `POS` is 1-based and `FLAG` is a bit mask (e.g. reverse strand, proper pair). The CIGAR `5M1I4M2D3M` consumes 13 read bases and 14 reference bases: `M` permits matches and mismatches, `I`/`D` are relative to the reference, `S` clips read bases. samtools handles alignment files; bcftools handles variants.

**Genotypes.** An allele is a sequence variant at a locus; a genotype is an individual's allele combination there. Reads sample chromosome copies noisily, so the genotype is inferred as

$$
P(G \mid D) \propto P(D \mid G)\, P(G).
$$

VCF `0/1` means REF/first ALT, unphased. In the lecture, allele counts mean distinct observed alleles.

## Ancient DNA {#ancient-dna}

Ancient DNA has short fragments, a low endogenous fraction, contamination and limited library complexity. **Deamination** (C→U) appears as terminal C→T (5′) and G→A (3′) changes; it causes errors but also helps authenticate ancient molecules. Short fragments map less uniquely, so lower mapping qualities are expected.

## Mapping in Practice: Seed, Extend, Trust the Placement {#from-exact-search-to-read-alignment}

Exact backward search alone cannot align reads containing mismatches or indels. Mapping is seed and extend:

::: steps

1. Find matching seeds with the index.
2. Locate and group compatible hits.
3. Extend candidates allowing mismatches and gaps.
4. Compare alternatives and assign MAPQ (best placement against the second best).

:::

- **BWA-aln**: the lecture illustrates a seed from the first 32 bases, followed by extension; the seed length is configurable.
- **BWA-MEM**: finds maximal exact-match seeds, chains compatible hits and extends candidates by local alignment.

Short reads and repeats create alternative placements. Longer reads and paired-end constraints often improve specificity. Indexing speeds up candidate discovery; extension produces the full alignment.

**Decisions**: trim adapters and low-quality ends before mapping; ==filter on MAPQ before variant calling==, because reads from repeats have several equally good placements and receive low MAPQ.

## Why Index the Reference {#why-index-the-reference}

Millions of reads must be mapped to a large genome, allowing errors and biological differences. Full DP against the genome for every read is too expensive, so the reference is preprocessed once and the index reused. Let $m$ be the reference length (including `$`) and $n$ the query length.

::: table align="center" title="Reference indexes compared"

| Index | Representation | Exact-search time |
| :--- | :--- | :--- |
| Suffix tree | Compressed tree of suffixes | $O(n)$ |
| Suffix array | Sorted suffix-start positions | $O(n \log m)$ |
| FM-index | Compressed BWT + rank support | $O(n)$* |

:::

\*Constant-time rank assumed; the interval/count search excludes locating all coordinates. FM-indexes need much less memory than explicit suffix trees: about 0.5 bytes per base (≈ 1.5 GB for the human genome, against ≈ 12 GB for a suffix array and ≈ 45 GB for a suffix tree).

## Suffix Array and BWT Construction {#building-the-bwt}

Append a unique terminator `$`, smaller than all letters. $SA[i]$ is the start position of the $i$-th sorted suffix; suffixes beginning with the same pattern form a contiguous interval.

**BWT**: generate all cyclic rotations, sort them lexicographically and take the last column $L$; the first column is $F$. For BANANA\$:

$$
SA = (7,6,4,2,1,5,3), \qquad F = \texttt{\$AAABNN}, \qquad L = \texttt{ANNB\$AA}.
$$

::: table align="center" title="Burrows–Wheeler matrix of BANANA$"

| Row | Sorted rotation | F | L | SA |
| :--- | :--- | :--- | :--- | :--- |
| 1 | `$BANANA` | \$ | A | 7 |
| 2 | `A$BANAN` | A | N | 6 |
| 3 | `ANA$BAN` | A | N | 4 |
| 4 | `ANANA$B` | A | B | 2 |
| 5 | `BANANA$` | B | \$ | 1 |
| 6 | `NA$BANA` | N | A | 5 |
| 7 | `NANA$BA` | N | A | 3 |

:::

Row 3, for instance, is `ANA$BAN`: suffix start 4, preceding character N. Each $L[i]$ precedes the corresponding suffix, wrapping around. Practical construction uses the suffix array without storing the full matrix. The BWT is reversible and groups similar contexts, which makes compression easier (both suffixes starting with ANA are preceded by N, giving the run NN); it does not itself shorten the string.

## LF Mapping and the FM-index {#lf-mapping}

> **Say:** The key is occurrence order: the first A in $L$ corresponds to the first A in $F$, the second to the second, and so on.

With 1-based positions and inclusive intervals:

$$
\begin{aligned}
C[c] &= \text{number of reference characters lexicographically smaller than } c, \\
\mathrm{Occ}(c, i) &= \text{number of } c \text{ characters in } L[1..i], \qquad \mathrm{Occ}(c, 0) = 0, \\
LF(i) &= C[L[i]] + \mathrm{Occ}(L[i], i).
\end{aligned}
$$

LF moves to the row whose suffix begins one reference position earlier, cyclically. Repeated LF steps recover the reference backwards; `$` anchors the reconstruction.

An **FM-index** contains the BWT, $C$, efficient Occ/rank support, and usually sampled suffix-array positions for locating matches. Sampling trades memory against locating time.

### Inverting the BWT {#inverting-the-bwt}

With $C$: \$ = 0, A = 1, B = 4, N = 5, start at row 1 (the row beginning with `$`); $L[1] = \text{A}$ is the last real letter of the text.

::: table align="center" title="LF walk that decodes BANANA"

| Step | Row $i$ | $L[i]$ | $LF(i)$ |
| :--- | :--- | :--- | :--- |
| 1 | 1 | A | $1 + 1 = 2$ |
| 2 | 2 | N | $5 + 1 = 6$ |
| 3 | 6 | A | $1 + 2 = 3$ |
| 4 | 3 | N | $5 + 2 = 7$ |
| 5 | 7 | A | $1 + 3 = 4$ |
| 6 | 4 | B | $4 + 1 = 5$ (row with $L = \$$, stop) |

:::

The collected letters A, N, A, N, A, B read backwards give BANANA.

## Backward Search: Interval, Count and Coordinates {#backward-search}

Process the query right to left. Maintain $[l, r]$, the interval of suffixes beginning with the processed query suffix; initially $[l, r] = [1, m]$. To prepend $c$:

$$
l' = C[c] + \mathrm{Occ}(c, l-1) + 1, \qquad r' = C[c] + \mathrm{Occ}(c, r).
$$

Only rows whose preceding character is $c$ survive, and LF maps them to the interval for the extended pattern. If $l' > r'$ there is no exact match. After the whole query, the count is $r - l + 1$. Coordinates come from $SA[l..r]$, or from LF walks to sampled SA positions.

**Lecture example.** Reference `AGACCCATGACC$`, BWT `CGG$CCCACATAA`:

::: table align="center" title="C table for AGACCCATGACC$"

| $c$ | `$` | A | C | G | T |
| :--- | :--- | :--- | :--- | :--- | :--- |
| $C[c]$ | 0 | 1 | 5 | 10 | 12 |

:::

::: table align="center" title="Backward search for GACC"

| Character added | Pattern matched | Interval |
| :--- | :--- | :--- |
| C | C | [6, 10] |
| C | CC | [8, 10] |
| A | ACC | [2, 3] |
| G | GACC | [11, 12] |

:::

For example, extending C to CC gives $l' = 5 + \mathrm{Occ}(C, 5) + 1 = 5 + 2 + 1 = 8$ and $r' = 5 + \mathrm{Occ}(C, 10) = 10$. The final count is $12 - 11 + 1 = 2$, and the reference starts are 2 and 9. ==The interval [11, 12] contains sorted row numbers, not genomic coordinates.== As an LF example, $L[6] = \text{C}$ and $LF(6) = 5 + 3 = 8$.

**BANANA example.** For the query ANA: A gives $[C[\text{A}]+1, C[\text{B}]] = [2,4]$; prepending N gives $l = 5 + \mathrm{Occ}(N,1) + 1 = 6$ and $r = 5 + \mathrm{Occ}(N,4) = 7$; prepending A gives $l = 1 + \mathrm{Occ}(A,5) + 1 = 3$ and $r = 1 + \mathrm{Occ}(A,7) = 4$. The interval [3, 4] has size 2, and $SA[3..4]$ gives positions 4 and 2.

::: table align="center" title="Occ counts for BANANA$"

| $i$ | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| L | A | N | N | B | \$ | A | A |
| Occ(A, i) | 1 | 1 | 1 | 1 | 1 | 2 | 3 |
| Occ(N, i) | 0 | 1 | 2 | 2 | 2 | 2 | 2 |
| Occ(B, i) | 0 | 0 | 0 | 1 | 1 | 1 | 1 |

:::

## Sequencing Technologies {#sequencing-technologies}

The revision sessions also asked about the instruments themselves.

- **Sanger (first generation)**: dideoxy chain termination and capillary electrophoresis; one template per reaction; reads of about 700–1000 bp with very high accuracy; low throughput and high cost per base.
- **Second generation (short reads, massively parallel)**: mainly **Illumina** sequencing by synthesis with reversible fluorescent terminators on clonal clusters from bridge amplification.
- **Third generation (single molecule, long reads)**: **Oxford Nanopore** (a single strand passes through a protein pore and the ionic current is decoded; reads from kb to Mb, real time, native DNA/RNA) and **PacBio** (SMRT; HiFi consensus reads).

::: table align="center" title="Illumina versus Nanopore"

| | Illumina (2nd gen) | Nanopore (3rd gen) |
| :--- | :--- | :--- |
| Principle | Sequencing by synthesis on clusters | Current through a pore, single molecule |
| Read length | 50–300 bp | kb to Mb |
| Errors | Low, mostly substitutions; quality drops towards read ends | Higher, mainly indels in homopolymers |
| Throughput / cost per base | Very high / low | Lower / higher (cheap device) |
| Strengths | SNPs, counting (RNA-seq), high depth, aDNA | De novo assembly, repeats, structural variants, phasing, full-length isoforms, methylation, field work |
| Weaknesses | Repeats, SVs, phasing, PCR/GC bias | Accuracy, homopolymers |

:::

A **fragment** (insert) is the physical DNA molecule between the adapters; a **read** is the sequence reported from one end (single-end) or both ends (paired-end). If the fragment is shorter than the read length, as in ancient DNA, the read runs into the adapter, which must be trimmed, and the paired reads overlap and can be merged.

## Ten-Minute Presentation {#presentation}

### Full Script {#full-script}

::: details Full spoken script

**What it is for.** Suppose I have sequenced a human sample, or DNA extracted from an ancient bone, and I get hundreds of millions of short reads. The reads by themselves say nothing; to find variants I must first decide where each read comes from in the reference genome, and how sure I am of that. So this topic has two halves: the practical workflow with the files and quality values that I actually look at, and the index, the Burrows–Wheeler transform, that makes mapping so many reads possible.

**The workflow.** DNA is fragmented and adapters are attached; this is the library. Illumina machines read the fragments by synthesis, often from both ends, giving paired-end reads. The reads arrive as a FASTQ file: for each read an identifier, the bases, and a quality character for every base. I check the quality and trim adapters, map the reads to a reference, which gives a SAM or BAM file, filter the alignments, and call variants, which gives a VCF file.

**Two kinds of quality.** Both are on the Phred scale, $Q = -10 \log_{10} P(\text{error})$, so $Q = 20$ means one error in a hundred and $Q = 30$ one in a thousand. Base quality answers: was this nucleotide read correctly? Mapping quality, MAPQ, answers a different question: is this read placed at the right position in the genome? A read can consist of perfect bases and still have mapping quality zero, because it comes from a repeat and fits equally well in several places. For variant calling I therefore filter on mapping quality, and I weight or filter bases by base quality.

**Reading an alignment record.** A SAM line gives the reference name, the leftmost position, counted from one, a flag whose bits say for example whether the read is on the reverse strand or is part of a proper pair, the mapping quality, and the CIGAR string. The CIGAR describes the alignment: M is an aligned position, match or mismatch, I an insertion and D a deletion relative to the reference, S soft-clipped bases. So `5M1I4M2D3M` uses 13 read bases and 14 reference bases. Ancient DNA has its own signature: fragments are short, and deamination of cytosine shows up as C-to-T changes at the ends of reads, which is a source of errors but also evidence that the molecules are really old.

**Why an index, and which one.** Aligning each read to the genome by dynamic programming is impossible at this scale, so I index the reference once and reuse it for all reads. A suffix tree would find a read in time proportional to its length but needs far too much memory for a human genome. The FM-index, built on the Burrows–Wheeler transform, gives the same search time in a few gigabytes. That is the reason mappers such as BWA and Bowtie are built on it.

**What the BWT is.** I append the end symbol to the reference, write down all cyclic rotations, and sort them alphabetically. The first column of this sorted matrix, F, is just all characters in sorted order. The last column, L, is the Burrows–Wheeler transform. For BANANA the transform is ANNB, the end symbol, AA. Two facts make it useful. First, each character in L is the character that precedes the suffix in the same row. Second, the occurrence-order property: the first A in the last column is the same text character as the first A in the first column, the second corresponds to the second, and so on. This is called the LF mapping, and it lets me step backwards through the text one character at a time.

**Backward search.** To search a read I process it from its last character to its first, and I keep an interval of rows: the rows whose suffixes begin with the part of the read processed so far. I need two small tables: $C[c]$, the number of characters in the text that are smaller than $c$, and $\mathrm{Occ}(c, i)$, the number of times $c$ occurs in the first $i$ positions of L. Adding a character $c$ in front updates the interval to $l' = C[c] + \mathrm{Occ}(c, l-1) + 1$ and $r' = C[c] + \mathrm{Occ}(c, r)$. If the interval becomes empty, the read does not occur. Otherwise its width is the number of occurrences. Each step is constant time, so the search takes time proportional to the read length, independent of the genome size.

**The lecture example.** For the reference AGACCCATGACC, searching GACC goes through the intervals [6, 10] for C, [8, 10] for CC, [2, 3] for ACC and [11, 12] for GACC. The final interval has width two, so GACC occurs twice. The interval gives the count; to get the genomic coordinates I need the suffix array, and to save memory only a sample of it is stored: from an unsampled row I walk backwards with the LF mapping until I reach a sampled one.

**From exact search to real mapping.** Reads contain sequencing errors and true variants, so exact search is not enough. Mappers use the index to find exact seeds, collect the candidate locations, and then extend with an alignment that allows mismatches and gaps. BWA-MEM, for example, finds maximal exact matches, chains those that are consistent, and extends them by local alignment. Finally it compares the best location with the second best and turns the difference into the mapping quality. Paired ends and longer reads help, because they make a placement in a repeat less ambiguous.

:::

## Follow-up Questions {#follow-up-questions}

::: note How to use these questions

Questions marked ★ were raised in the revision sessions on 27 and 29 October. Answer directly first, then justify with the model, then name an assumption or limitation. Each answer is collapsed so the list can be used for self-testing.

:::

::: collapse

- What is the difference between base quality and mapping quality?

  Base quality is the sequencer's confidence in one nucleotide. Mapping quality is the mapper's confidence that the whole read is placed at the correct genomic position. A read from a repeat can have high base qualities and a mapping quality of zero.

- What error probability does Q30 correspond to, and Q10?

  $10^{-3}$, one in a thousand, and $10^{-1}$, one in ten. Every ten points is a factor of ten.

- Why is the BWT useful for searching if it is just a permutation of the text?

  Because together with the $C$ table and the occurrence counts it implicitly contains the sorted suffixes: the LF mapping lets me go from a row to the row of the suffix that starts one position earlier. That is enough to do the same interval search as in a suffix array without storing the array, and the BWT compresses well.

- Why is the search done backwards?

  Because the character in the last column is the one that precedes the suffix. So from the rows that start with a pattern I can cheaply find the rows that start with one more character in front of it, but not one more character behind it.

- The backward search ends with an interval of width three. What do you know and what do you still need?

  The pattern occurs three times. I do not yet know where: for the positions I need the suffix array values of these three rows, obtained from the sampled suffix array, walking back with LF until a sampled row is reached.

- ★ Give a full BWT walkthrough including decoding.

  BANANA\$: sorted rotations `$BANANA, A$BANAN, ANA$BAN, ANANA$B, BANANA$, NA$BANA, NANA$BA`; $L$ = ANNB\$AA, $F$ = \$AAABNN, SA = 7 6 4 2 1 5 3, $C$: \$ 0, A 1, B 4, N 5. Decoding with $LF(i)$ from row 1: row 1 (A) → 2 (N) → 6 (A) → 3 (N) → 7 (A) → 4 (B) → stop; read backwards: BANANA. Search ANA: [2,4] → [6,7] → [3,4] → SA gives 4 and 2.

- ★ Why does the BWT allow compression? Is it lossy?

  Sorting rotations groups together characters that precede the same context, so repeated substrings produce runs of the same character (NN and AA in BANANA; long runs in repetitive genomes), which compress well with run-length or move-to-front coding. The BWT itself has the same length and is lossless: it is inverted exactly with the LF mapping.

- Why can a read not always be mapped uniquely, and what helps?

  Genomes contain repeats and duplicated regions longer than the read, so several positions fit equally well. Longer reads, paired-end information with a known insert size, and filtering on mapping quality help.

- What is special about mapping ancient DNA?

  The fragments are very short, so they map less uniquely; much of the DNA is from microbes or modern contamination; and damage gives C-to-T mismatches at the read ends. I expect lower mapping qualities, I treat terminal mismatches with care, and I use the damage pattern to authenticate the data.

- ★ Walk through an ancient DNA workflow.

  Clean-lab sampling and contamination control → extraction retaining short fragments → library building (indexed adapters, optionally USER enzyme to remove uracils) → amplification and Illumina paired-end sequencing → QC, adapter trimming and merging of overlapping pairs → mapping with BWA-aln (short reads, relaxed settings) → sort, mark or remove PCR duplicates → filter by MAPQ and length → authenticate with the damage pattern (C→T at 5′, G→A at 3′), fragment length and contamination estimates → genotype likelihoods or pseudo-haploid calls. Library complexity limits how much useful data can be obtained; the endogenous fraction determines cost.

- ★ What is the difference between Illumina and Nanopore? When would you use second- versus third-generation sequencing?

  Illumina: sequencing by synthesis on clonal clusters, 50–300 bp reads, very accurate (errors mostly substitutions), enormous throughput and cheap per base, but short reads cannot resolve long repeats or structural variants or phase haplotypes. Nanopore: single molecules through a pore, kb to Mb reads in real time, native DNA/RNA and base modifications, but a higher error rate (indels, homopolymers). Short reads for accurate SNP calling, large cohorts, counting and short or degraded DNA such as aDNA; long reads for de novo assembly, repeats, structural variants, phasing, full-length isoforms and field diagnostics. Hybrid approaches combine both.

- ★ What was there before NGS?

  Sanger sequencing: dideoxy chain termination with capillary electrophoresis, one template per reaction, ~700–1000 bp reads with very high accuracy, low throughput and high cost per base. It was used for the Human Genome Project and is still used to validate single loci.

- ★ What is the difference between a fragment and a read?

  The fragment (insert) is the physical DNA molecule in the library between the adapters; the read is the sequence the instrument reports from one or both ends of it, limited by read length. A 500-bp fragment with 2×150 reads leaves 200 bp unsequenced in the middle; a 40-bp aDNA fragment with 150-bp reads gives adapter read-through and fully overlapping pairs.

- ★ Explain the Illumina sequencing process. Where does reverse transcriptase come in?

  Fragment DNA → end repair, A-tailing and adapter ligation with indexes → bridge amplification into clonal clusters on the flow cell → cycles of fluorescent reversible terminators with imaging → base calls with Phred qualities → demultiplex by index → FASTQ. Illumina reads DNA, so RNA must first be reverse-transcribed into cDNA; Nanopore can read native RNA directly. Ancient DNA needs no reverse transcription.

:::
