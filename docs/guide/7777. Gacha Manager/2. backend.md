## Overview {#overview}

The **Gacha Metadata API** provides public item information for Gacha Manager: send a game, language and item IDs to retrieve names, rarity, types and icons. It runs on **Cloudflare Workers + D1**. Queries read the database; scheduled jobs and maintenance endpoints update upstream metadata.

<RepoCard repo="Lucas04-nhr/Gacha-Manager" />

The API service supports three games: Genshin Impact (including Miliastra Wonderland), Honkai: Star Rail, Zenless Zone Zero, with 4 languages: English, Simplified Chinese, Traditional Chinese and Japanese. Miliastra Wonderland outfits are included in the built-in sources, but only Chinese metadata is available.

==**Requests need public item IDs only.**== The service does not require any user-specific information. It is the frontend that handles UIGF import/export, incremental record fetching, display and local storage. There is no account system or banner schedule API.

::: table title="Game and type mapping" align="center"
| Game | Content | D1 table | Unified `type` |
| --- | --- | --- | --- |
| Genshin Impact (`hk4e`) | Genshin Impact characters and weapons | `genshin_meta` | `character`, `weapon` |
| Genshin Impact UGC (`hk4e_ugc`) | Miliastra Wonderland outfits and related rewards | `genshin_ugc_meta` | Automatic sync uses `ugc_item`; manual updates also support `outfit` |
| Honkai: Star Rail (`hkrpg`) | Honkai: Star Rail characters and Light Cones | `starrail_meta` | `character`, `light_cone` |
| Zenless Zone Zero (`nap`) | Zenless Zone Zero agents, W-Engines and Bangboo | `zenless_meta` | `character`, `w_engine`, `bangboo` |
:::

The primary key is `(namespace, kind, lang, entity_id)`. Only `kind=item` is maintained. The `DB` binding points to the existing `gacha_meta` database; no KV, R2 or Durable Objects are needed.

::: tabs
@tab Enka and Dimbreath

Ordinary characters and equipment for the three games come primarily from the [Enka processed store](https://github.com/EnkaNetwork/API-docs/tree/master/store). Only public static files are read; player APIs are not called.
<RepoCard repo="EnkaNetwork/API-docs" />
Existing Enka values take precedence. Dimbreath configuration files and text maps are read only to complete missing names, ranks or icons. A failed primary download does not trigger replacement of the entire source. Entries that remain incomplete are skipped without deleting existing database rows. ZZZ currently has no reliable fallback mapping for ranks or icons, so those values are not guessed.

@tab Starward special items

Bangboo metadata comes from Starward's `ZZZGachaInfo.nap_global.<lang>.json`. Only IDs in the `5xxxx` range are imported, using type `bangboo`.
<RepoCard repo="Scighost/Starward" />
Miliastra metadata comes from `GenshinBeyondGachaInfo.json`, including outfits and related rewards. This source currently provides Chinese names only, so entries are stored under `zh-cn` in a separate table. Unnamed entries are skipped.

@tab Coverage

Upstream stores may include items unavailable through gacha and may omit new items or languages. The API looks up metadata by ID; it does not determine whether an item belongs to a current banner.

`source` records provenance. Items completed using Dimbreath retain Enka as the primary source; completion counts appear in `metadata_fallback` logs.
:::

## Public query API {#public-api}

The public base URL is `https://gachameta.lucas04.top`; local development uses `http://localhost:8787`.

::: info Rate Limit
The service runs on a free tier of Cloudflare Workers, which has a global limit of 100,000 requests per day. . If an `1015` or `429` error occurs, retry after a few seconds or try to request fewer items.
:::

::: table title="Public endpoints" align="center"
| Path | Purpose | Successful response and caching |
| --- | --- | --- |
| `/` | Plain-text welcome message and documentation link | `text/plain`, 300 seconds |
| `/api/v1/health` | Check that all four business tables can be queried | JSON, `no-store` |
| `/api/v1/games` | Supported games, languages and query limits | JSON, 3600 seconds |
| `/api/v1/items` | Batch lookup by item ID | JSON, 300 seconds |
:::

Public endpoints support `GET`, `HEAD` and `OPTIONS` without authentication. `HEAD` returns no body. Browser preflight permits GET/HEAD without custom headers. Public requests use `credentials: 'omit'`.

### Item query parameters {#item-query}

:::: field-group
::: field game
@type string
@required
Case-sensitive game identifier: `hk4e`, `hkrpg`, `nap` or `hk4e_ugc`.
:::
::: field lang
@type string
@optional
@default en-us
A complete language code listed by `/api/v1/games`. No automatic language fallback is performed. Use `zh-cn` for the built-in Miliastra source.
:::
::: field ids
@type string
@required
Between 1 and 90 comma-separated decimal string IDs. Each ID must contain 1–20 digits, without spaces or empty segments. Example: `10000003,11401`.
:::
::::

Only these three parameters are permitted, each appearing once. Repeated parameters and player fields are rejected. A query string longer than 4096 characters returns 414.

The service checks the original ID count before deduplication and returns `items` in deduplicated request order. Repeated IDs therefore still count toward the 90-ID input limit. Keep IDs as strings to avoid JavaScript numeric precision loss.

::: code-tabs
@tab request.sh

```bash
curl 'https://gachameta.lucas04.top/api/v1/items?game=hk4e&lang=en-us&ids=10000003,11401'
```

@tab request.js

```js
const base = 'https://gachameta.lucas04.top';
const ids = ['10000003', '11401'];
const params = new URLSearchParams({
  game: 'hk4e',
  lang: 'en-us',
  ids: ids.join(','),
});
const response = await fetch(`${base}/api/v1/items?${params}`, {
  credentials: 'omit', // [!code highlight]
});
const payload = await response.json();
if (!response.ok) {
  throw new Error(payload.error?.message ?? `HTTP ${response.status}`);
}
console.log(payload.data, payload.missing_ids);
```

@tab request_miliastra.js

```js
// publicItemIds contains the public item IDs to look up.
const params = new URLSearchParams({
  game: 'hk4e_ugc',
  lang: 'zh-cn', // [!code highlight]
  ids: publicItemIds.join(','),
});
```

:::

::: warning No automatic language fallback
An `en-us` query reports an ID in `missing_ids` even when a `zh-cn` record exists for that ID. The built-in Miliastra source currently writes Chinese metadata only; explicitly request `lang=zh-cn`.
:::

#### Response envelope

:::: field-group
::: field game
@type string
The queried game identifier.
:::
::: field lang
@type string
The requested language, or `en-us` when omitted.
:::
::: field items
@type PublicItem[]
Detailed item records in request order after deduplication. Includes raw ranks, provenance and update timestamps.
:::
::: field data
@type Record<string, ItemMetadata>
Dictionary keyed by item ID. Each value contains `name`, `rank`, `type` and `icon` for frontend display.
:::
::: field missing_ids
@type string[]
IDs not found for the requested game and language. No placeholder item is generated.
:::
::::

#### Detailed item record

The following fields describe each object in `items`. Nullable fields are returned with `null` when unavailable; they are not optional response properties.

:::: field-group
::: field item_id
@type string
The public item ID, preserved as a decimal string.
:::
::: field name
@type string
The localized name stored for the requested language.
:::
::: field rank_type
@type string | null
The raw rank supplied by the source or maintainer.
:::
::: field rank
@type number | null
Display rank: GI/HSR use 3/4/5; ZZZ raw values 2/3/4 map to 3/4/5. Miliastra uses 1–5 directly; 0 or an unknown rank returns `null`.
:::
::: field rarity
@type number | null
Alias of `rank`, with the same display value.
:::
::: field type
@type string | null
Unified category from the game/type table above. Legacy rows without a category return `null`.
:::
::: field item_type
@type string | null
Type text supplied by the maintainer. Automatic synchronization normally uses the unified category value.
:::
::: field icon
@type string | null
Icon URL. Legacy rows without an icon return `null`.
:::
::: field source
@type string
Metadata provenance URL.
:::
::: field updated_at
@type string
ISO timestamp of the metadata write, not a player's gacha timestamp.
:::
::::

A query with no matches still returns **200**, with an empty `items` array and `data` object. Preserve the original ID and display a label such as “Metadata unavailable”; do not infer a name or rank. Successful queries use `Cache-Control: public, max-age=300`, so an update may briefly return cached data. Health checks do not verify cache freshness.

## Local development and deployment {#deployment}

Run these commands from the **Gacha Manager repository root**. The backend uses npm, separately from this blog's pnpm workflow. It requires Node.js 22.18+ or a newer version supported by Wrangler. You can install all the dependencies easily using Homebrew by `brew install node@22 wrangler`. The `wrangler` CLI is used to run, test and deploy the Worker.

::: steps

1. Get the source and install dependencies

   ```bash
   git clone https://github.com/Lucas04-nhr/Gacha-Manager.git
   cd Gacha-Manager
   wrangler --version
   ```

2. Check the code and migrate local D1

   ```bash
   npm run types
   npm run check
   npm run db:migrate:local
   ```

   `types` generates Worker types; `check` runs TypeScript checking. Migrations create or update tables without downloading metadata. Local D1 does not modify production data.

3. Start and verify the service

   ```bash
   npm run dev
   ```

   In another terminal:

   ```bash
   curl 'http://localhost:8787/api/v1/health'
   curl 'http://localhost:8787/api/v1/items?game=hk4e&lang=en-us&ids=10000003'
   ```

   Before importing data, `missing_ids` is expected. `npm run build` performs a deployment dry run. `npm test` uses local workerd/D1 and mocked upstream sources; it does not verify production metadata.

4. Configure your Cloudflare resources

   When deploying your own instance, replace the account ID, D1 database ID, routes and domain in `wrangler.jsonc`. Point `DB` to your own `gacha_meta` database instead of retaining the author's resource identifiers. Apply all migrations in `migrations/` for the four tables.

5. Deploy and populate metadata

   ```bash
   wrangler login
   wrangler secret put METADATA_UPDATE_TOKEN
   npm run db:migrate:remote
   npm run deploy
   ```

   Remote migrations modify the bound production D1 database; `deploy` publishes the Worker. Check `/api/v1/health`, run the admin synchronization endpoint, then query imported IDs. These instructions do not imply that any remote operations have already been performed.
   :::

### Configuration {#configuration}

This is a configuration fragment for `wrangler.jsonc`. Lists inside environment variables are **JSON-encoded strings**.

```json
{
  "vars": {
    "ALLOWED_ORIGINS": "*",
    "UPSTREAM_SYNC_ENABLED": "true",
    "UPSTREAM_LANGUAGES": "[\"en-us\",\"zh-cn\",\"zh-tw\",\"ja-jp\"]",
    "METADATA_FEEDS": "[]"
  },
  "triggers": { "crons": ["0 3 * * *"] }
}
```

:::: field-group
::: field ALLOWED_ORIGINS
@type string
@default _
Public CORS origins. Use a comma-separated list of complete origins, such as `https://blog.example.com`, to restrict browser access.
:::
::: field UPSTREAM_SYNC_ENABLED
@type string
@default 'true'
Set to `false` to disable built-in sources. Additional feeds can still run.
:::
::: field UPSTREAM_LANGUAGES
@type string
@default ["en-us","zh-cn","zh-tw","ja-jp"]
JSON-encoded language list for the three games and Bangboo. Miliastra always synchronizes Chinese only. Accepted languages may still be unavailable from an upstream source.
:::
::: field METADATA_FEEDS
@type string
@default []
JSON-encoded list of up to eight additional normalized feed URLs. Feeds run after built-in sources and can override matching records.
:::
::: field METADATA_UPDATE_TOKEN
@type Secret
@required
A random secret of 32–512 characters for admin authentication. Required for admin endpoints; public queries and Cron do not depend on it. Set it using `wrangler secret put`, rather than adding it to `vars`.
:::
::: field triggers.crons
@type string[]
@default ["0 3 * * *"]
Runs daily at **03:00 UTC**. Changes to Cron or deployment configuration require redeployment.
:::
::::

CORS restrictions are not authentication: server requests without an `Origin` header can still query public metadata. Public clients omit credentials. Keep the admin token in maintainer scripts or CI secrets, never in the frontend.

Additional feeds require public HTTPS domain URLs without credentials, explicit ports, query strings or fragments. Query requests cannot choose a fetch destination. Each feed is limited to 2000 entries and 1 MiB and uses the normalized payload below.

## Metadata maintenance {#maintenance}

Both admin endpoints are for maintainer scripts or CI: they require `POST` and `Authorization: Bearer <token>`, accept no query parameters, reject any browser `Origin` header and do not enable CORS.

Set a random production token interactively with `wrangler secret put METADATA_UPDATE_TOKEN`. For local development, use the Git-ignored `.dev.vars` file. Missing or invalid-length secrets cause admin endpoints to return 503; public queries and Cron remain independent of this secret.

### Immediate synchronization {#sync}

`POST /api/v1/admin/sync` accepts no request body and runs the same synchronization as Cron. Configure `GACHA_API_BASE` and `GACHA_ADMIN_TOKEN` through the environment or CI secret store before running this Node.js script. Do not place real tokens in source files or shell history.

::: code-tabs
@tab sync.mjs
```js
// Save as sync.mjs and run node sync.mjs.
const base = process.env.GACHA_API_BASE;
const token = process.env.GACHA_ADMIN_TOKEN;
if (!base || !token) throw new Error('Missing API base URL or admin token');
const response = await fetch(`${base}/api/v1/admin/sync`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}` },
});
const result = await response.json();
if (!response.ok) {
  throw new Error(`${response.status}: ${result.error?.code}`);
}
console.log(result); // Example: { updated: 123, sources: 9 }; counts are illustrative.
```
:::

`updated` counts written entries, including updates to existing records. `sources` counts jobs and additional feeds, not distinct upstream websites.

::: warning Successful tasks remain committed after partial failure
Each game/language task commits independently. A failure does not prevent later tasks from running. If any task fails, the overall request returns 502 `SYNC_FAILED`; successful tasks are not rolled back. Inspect the failing game, language or feed index, fix the source and retry.
:::

Test Cron locally:

```bash
wrangler dev --test-scheduled
```

In another terminal:

```bash
curl 'http://localhost:8787/cdn-cgi/local/scheduled?cron=0+3+*+*+*'
```

### Manual updates {#manual-metadata}

`POST /api/v1/admin/metadata` requires `Content-Type: application/json`, rejects compressed request bodies and accepts at most 2000 entries within 1 MiB. Save this example as `metadata.json`.

::: code-tabs
@tab metadata.json

```json
{
  "source": "https://github.com/EnkaNetwork/API-docs/tree/master/store/gi",
  "entries": [{
    "game": "hk4e",
    "lang": "en-us",
    "kind": "item",
    "item_id": "10000003",
    "name": "Jean",
    "item_type": "character",
    "rank_type": "5",
    "type": "character",
    "icon": "https://enka.network/ui/UI_AvatarIcon_Side_Qin.png"
  }]
}
```

@tab update.mjs

```js
import { readFile } from 'node:fs/promises';

const base = process.env.GACHA_API_BASE;
const token = process.env.GACHA_ADMIN_TOKEN;
if (!base || !token) throw new Error('Missing API base URL or admin token');
const response = await fetch(`${base}/api/v1/admin/metadata`, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${token}`,
    'Content-Type': 'application/json',
  },
  body: await readFile('metadata.json', 'utf8'),
});
const result = await response.json();
if (!response.ok) throw new Error(`${response.status}: ${result.error?.code}`);
console.log(result); // Successful responses contain updated and updated_at.
```
:::

#### Payload fields

:::: field-group
::: field source
@type string
@required
HTTPS provenance URL, at most 2048 characters, without credentials, query strings or fragments.
:::
::: field entries
@type MetadataEntry[]
@required
Between 1 and 2000 normalized metadata entries for an HTTP update. Duplicate game/kind/language/ID keys are rejected.
:::
::::

Each entry has the following schema:

:::: field-group
::: field game
@type string
@required
One of `hk4e`, `hkrpg`, `nap` or `hk4e_ugc`.
:::
::: field lang
@type string
@required
A supported language code. Unlike public queries, manual entries do not default to `en-us`.
:::
::: field kind
@type string
@required
Must be `item`. Banner schedules are unsupported.
:::
::: field item_id
@type string
@required
A decimal string of 1–20 digits. Numeric JSON values are rejected.
:::
::: field name
@type string
@required
Nonempty localized item name, at most 256 characters, without control characters.
:::
::: field item_type
@type string
@required
Nonempty type text, at most 64 characters, without control characters.
:::
::: field rank_type
@type string
@required
Raw decimal rank string. GI/HSR accept `3`, `4` or `5`; ZZZ accepts `2`, `3` or `4`. Miliastra accepts decimal strings, while only 1–5 become non-null display ranks.
:::
::: field type
@type string
@optional
Unified category allowed for the selected game. Omitting it preserves an existing category during an update.
:::
::: field icon
@type string
@optional
HTTPS icon URL without credentials, at most 2048 characters. Omitting it preserves an existing icon during an update.
:::
::::

Unknown fields, invalid ranks and duplicate keys are rejected. All entries are validated before one atomic D1 batch upsert; rows absent from the request remain unchanged. This differs from automatic synchronization, where multiple tasks commit separately. A later built-in sync can overwrite manual changes; use a maintainer-configured feed for recurring overrides.

### Offline SQL import {#offline-import}

To maintain data without an admin HTTP request, validate local JSON and generate SQL:

```bash
npm run metadata:sql -- metadata.json metadata.sql
wrangler d1 execute gacha_meta --local --file metadata.sql
```

The generator does not access the network, modify a database or overwrite an existing output file. Choose a different output filename or manage the old file yourself. The subsequent `d1 execute` command writes to local D1. Do not import test fixtures as production metadata.

## Errors and troubleshooting {#troubleshooting}

Errors use this structure with `Cache-Control: no-store`. SQL and raw exceptions are not exposed.

```json
{
  "error": {
    "code": "INVALID_IDS",
    "message": "ids must contain 1–90 comma-separated decimal strings, each at most 20 digits."
  }
}
```

::: table title="Common error codes" align="center"
| HTTP | Common error codes | What to check |
| --- | --- | --- |
| 400 | `INVALID_QUERY`, `INVALID_GAME`, `INVALID_LANGUAGE`, `INVALID_IDS` | Parameter names, repetition, game/language codes, ID format and count |
| 400 | `INVALID_BODY`, `INVALID_JSON`, `INVALID_METADATA` | Empty sync body; valid UTF-8 JSON and metadata fields for manual updates |
| 401 | `UNAUTHORIZED` | Admin token and Bearer header format |
| 403 | `ORIGIN_NOT_ALLOWED`, `ADMIN_BROWSER_DISABLED` | Origin allowlist; use a maintainer script for admin endpoints |
| 404 | `NOT_FOUND` | Endpoint path; banner APIs are not implemented |
| 405 | `METHOD_NOT_ALLOWED` | GET/HEAD for queries, POST for admin; preflight headers |
| 413 | `PAYLOAD_TOO_LARGE` | Update payload exceeds 1 MiB |
| 414 | `QUERY_TOO_LONG` | Query string exceeds 4096 characters |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | JSON Content-Type; no Content-Encoding |
| 502 | `SYNC_FAILED` | Upstream task failure; some updates may already be committed |
| 503 | `DATABASE_UNAVAILABLE`, `UPDATES_DISABLED` | DB binding and migrations, or admin secret length |
:::
